## 3. Surprises / things to remember

These are gathered from task reports throughout P1. Each is load-bearing for future phases or onboarding.

### Build environment

- **Metal Toolchain on macOS**: `gpui`'s `build.rs` requires the Metal Toolchain. Xcode 26.3 doesn't ship it by default — run `xcodebuild -downloadComponent MetalToolchain` (~700MB). Already added to T20 CI. **Action**: add to dev onboarding section of `README.md` when one is written.

- **`gpui` migrated to crates.io**: T0 spike found that `gpui` v0.2.2 is now published to crates.io and `gpui-component` v0.5.1 consumes it via `gpui = "0.2.2"`. The plan was authored against a git-rev pin assumption. Actual pin form: `gpui = "=0.2.2"` + `gpui-macros = "=0.2.2"` from crates.io, plus `gpui-component` git rev `0f0ab35`. Documented in `docs/internal/gpui-api-notes.md`.

- **`gpui-component` v0.5.1 ships first-party `setting` module** (T0 §0.5/0.5b finding). Should reduce T16-equivalent scope when settings UI moves from scaffold to real widgets in P3.

### Hidden requirements

- **`Root::new(view, window, cx)` + `gpui_component::init(cx)` are mandatory** for dialogs, sheets, and notifications to render. Without both, T17 primitives silently fail. T2 + T14 preserve the wiring; T17 documented to depend on it. Any window creation in P2+ must preserve this initialization order.

### Plan defects discovered during implementation

- **`notify::Watcher::watch()` errors on non-existent path**. T21 boot orchestration had to add `if !settings_path.exists() { store.save(&initial)?; }` to seed the file before attaching the watcher. Verbatim wiring per the plan would have failed the boot test on a clean host.

- **Tracing `EnvFilter` directive**: plan specified `"info,dat0=debug"`. Tracing matches by module path with underscores (`dat0_app`, `dat0_engine`, `dat0_format`, `dat0_i18n`, `dat0_keychain`), not by the original crate name. The directive `dat0` matches none of dat0's crates. Filter is currently broken for dat0 crate logs at debug level. **Action for P2**: replace with `info,dat0_app=debug,dat0_engine=debug,dat0_format=debug,dat0_i18n=debug,dat0_keychain=debug` (or a glob if `tracing-subscriber` supports one in the version we pinned).

- **rustfmt unstable keys**: `imports_granularity` and `group_imports` only work on nightly rustfmt; emit warnings on stable. T1 follow-up dropped them. Decision deferred to T20+ on whether we want a nightly-fmt CI job.

- **`cargo-about` v0.9.0 schema change**: requires `--features=cli` on install; `targets` is a top-level array, not a `[targets]` table; the Handlebars template must NOT emit its own BEGIN/END markers (the binary emits them). All applied in T18.

### CI / infrastructure observations

- **CI verification deferred**. `.github/workflows/ci.yml` and `notice.yml` are authored but no run has happened (branch not pushed). First push will validate the workflow. Surprises are likely on Linux aarch64 cross-compilation specifically.

- **`GLITCHTIP_DSN_PUBLIC` secret unset** in the repo. Runtime telemetry init silently no-ops against an empty/invalid DSN. Acceptable for P1; needs to be set in repo secrets before P11 launch.

- **Apple Developer Program enrollment**: not yet done (P0 noted as longest external lead time). Required for T20 CI signing/notarization steps to actually produce signed artifacts. The workflow steps will succeed on unsigned builds.

### Atomic write caveat

- **`fsync` on atomic write**: T8 settings store does write-temp-then-rename, but does not currently `fsync` the temp file before rename, nor `fsync` the parent directory after. On a power loss during settings save, the rename may be visible while the file content is empty/partial. Add to P2 hardening pass.
