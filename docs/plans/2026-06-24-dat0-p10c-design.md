# dat0 P10c — Crash Reporting End-to-End + Settings Hardening

> **Design doc.** Brainstormed 2026-06-24. Fourth and (for now) final slice of P10
> ("Hardening + perf gates + signing", master spec §21.2). Scopes P10c to the one
> externally-gated subsystem whose infrastructure now exists — **GlitchTip crash
> reporting** — plus the zero-external-dependency **D-029** settings/cleanup debt
> filed by the P10b final review. The two remaining P10-exit gaps (GPU perf-gate
> runner, beta channel) stay deferred because their external prerequisites still do
> not exist. Next step after user review: `writing-plans`.

---

## 1. Why this slice exists

The P10a split (2026-06-17, `docs/plans/2026-06-17-dat0-p10a-design.md` §1) partitioned
P10 four ways and parked P10c as the "externally-gated tail":

| P10c piece | External prerequisite | Status 2026-06-24 |
|---|---|---|
| GlitchTip crash-submit flip + e2e | a provisioned GlitchTip (Sentry-compatible) instance + DSN | **NOW AVAILABLE** |
| GPU perf-gate runner (D-013) | dedicated Apple Silicon Mac mini | still absent → stays deferred |
| Beta channel kickoff | ≥20 invited testers + nightly distribution + feedback surface | still absent → stays deferred |

Only the GlitchTip prerequisite has materialized. So P10c scopes to **what is now
executable**: the crash-reporting end-to-end path, plus the **D-029** debt (which has
no external dependency and was explicitly tagged "do together in P10c"). The perf-gate
runner and beta channel remain deferred — their gates are unchanged — and are the only
two P10-exit criteria P10c does not close.

This keeps P10c a coherent, shippable slice rather than a grab-bag blocked on hardware
and people that do not yet exist.

## 2. Scope / non-goals

**In scope (P10c):**

- **Workstream A — Crash reporting (medium model).** Wire the real GlitchTip DSN;
  add the user-facing trust surfaces the spec calls for (a post-crash **relaunch
  dialog** with a free-form note, and an always-available **"Report a bug"** action);
  harden the `before_send` redaction tests now that events actually transmit; prove
  the path end-to-end with a **soft** CI round-trip gate plus a manual UAT.
- **Workstream B — D-029.** Change-gate the Settings panel's persist-on-render
  (per-frame fsync) smell; the P10b cleanup trio (orphan `SettingsView`/`render`
  trait, two hardcoded input placeholders, one orphan i18n key); and correct the
  false "i18n-check fails on missing keys" claim, adding a real (warn-only)
  referenced-key resolution check.
- **Docs.** Extend `docs/release-runbook.md` with a GlitchTip ops section.

**Non-goals (explicit — each stays where it is):**

- **GPU perf-gate runner / merge-blocking perf budgets.** → D-013 stays open,
  re-targeted to "when a dedicated Mac mini lands." Advisory benches already run in
  CI (macOS grid-scroll on push-to-main); P10c does **not** flip any bench to a
  merge gate.
- **Beta channel / tester cohort / nightly distribution.** → stays deferred. The
  `release.yml` machinery from P10a already exists; the missing piece is people, not
  code.
- **Full SQLite `telemetry.queue` + batched submission** (the spec's aspirational
  architecture, §architecture). Rejected for P10c: a batched durable queue is
  over-built for an opt-in, crash-only event stream. A single staged-crash file is
  sufficient for the relaunch-dialog model (see D2). Revisit in v1.x only if a richer
  event stream (usage analytics) is ever added.
- **AccessKit / screen-reader tree (D-015).** Unrelated; stays open (GPUI pin
  lacks an adapter).
- **Settings schema version bump.** The telemetry settings (`crash_submission_enabled`)
  already exist; no new persisted field is required.

| # | Decision | Over | Because |
|---|---|---|---|
| D1 | Scope P10c to GlitchTip + D-029 only; keep perf-gate + beta deferred | "P10c = the whole externally-gated tail" | Only the GlitchTip prerequisite now exists; HW + testers are unchanged from the P10a split. Scoping to the executable slice keeps it coherent. |

| D4 | **Soft** CI e2e gate (`continue-on-error`) from day one + manual UAT | hard CI gate; manual-only | The `ai_live` live-API **hard** gate flaked `main` red for ~3h (P10a) and became a soft-gate candidate. | D5 | i18n-check key-resolution addition is **warn-only** (`exit 0`) | make it a hard failing gate | `i18n-check.sh` is warn-only today; introducing a surprise hard gate mid-phase risks reddening unrelated PRs. Document the correct behavior; add resolution as a warning. |

## 4. As-built starting point (verified 2026-06-24)

- **The "flip" is already wired.** `crates/dat0-app/src/telemetry/mod.rs`
  `Telemetry::init(submission_enabled)`: when `true`, parses the DSN + calls the real
  `sentry::init` with the `before_send` redaction hook → events transmit; when
  `false`, returns a no-op handle (no client). `boot.rs:75` passes
  `initial.telemetry.crash_submission_enabled`. So "captured-locally → submit" is
  effectively done in code — what is missing is the real DSN, the user surfaces, and
  the proof.
- **No local capture / queue exists today.** Opt-out = total no-op (not "captured
  locally"). The spec's `telemetry.queue` SQLite store, `TelemetryService`, and
  auto-flush are **not** implemented. P10c does not add them (D2).
- **Sentry crate:** `sentry = "0.36"`, `default-features = false`, features
  `["backtrace", "panic", "rustls", "reqwest"]`. The `panic` feature provides the
  panic integration (auto-capture); `reqwest` is the transport. The relaunch-dialog
  model layers a custom panic hook for **staging** on top of / in place of the default
  capture-and-send-at-crash behavior (see §5.A1), so the note can be attached on
  relaunch rather than producing a second event.
- **DSN wiring:** `SENTRY_DSN_PUBLIC = env!("DAT0_GLITCHTIP_DSN_PUBLIC")`.
  `.cargo/config.toml` supplies the stub `https://stub@glitchtip.invalid/1`; `ci.yml`
  and `heavy.yml` already pass `DAT0_GLITCHTIP_DSN_PUBLIC: ${{ secrets.GLITCHTIP_DSN_PUBLIC }}`.
  Per the repo-locations note the `GLITCHTIP_DSN_PUBLIC` secret is **not set** yet —
  an operator action P10c documents.
- **Settings toggle exists:** `settings_ui/sections/telemetry.rs`
  `set_crash_submission_enabled` + the panel toggle (`panel.rs:108/120`) are built and
  tested. P10b shipped the real Settings window.
- **D-029 orphans confirmed present:** `settings_ui/mod.rs` `struct SettingsView`
  (:26) + `impl Render for SettingsView` (:74); `settings_ui/sections/mod.rs`
  `trait SettingsSection` (:25) with `fn render(...)` (:33). Both `pub`, instantiated/
  called nowhere → safe deletions.
- **Redaction:** `telemetry/redaction.rs` (`redact_event`) is the privacy-critical
  `before_send` hook documented in P10b `docs/privacy.md`. Now that events transmit,
  its tests are load-bearing.
- `main.rs` delegates to `boot`; the exact clean-shutdown point (where the crash
  sentinel is removed) and the panic-hook install site are planning-level details to
  pin during `writing-plans`.

## 5. Architecture

### 5.A Workstream A — Crash reporting (medium model)

**A1 — Capture + staging + relaunch dialog.**
- **Crash sentinel.** At boot, write a `running.marker` file under the app data dir
  (`${XDG_DATA_HOME:-~/.local/share}/dat0/` on Linux; the macOS equivalent). Remove
  it at clean shutdown. A surviving marker on next launch ⇒ the prior run exited
  abnormally.
- **Panic hook.** Install a panic hook (chained with sentry's) that stages a redacted
  `last-crash.json` (event payload + backtrace + version + timestamp) at panic time.
  Staging does **not** rely on the dying process flushing the network transport. The
  default capture-and-send-at-crash is suppressed in favor of staged relaunch submit
  so the event is sent **once**, with the note.
- **Relaunch handling.** On next launch, if the marker survived **and**
  `crash_submission_enabled` is `true`:
  - staged `last-crash.json` present (a Rust panic) ⇒ show a blocking dialog
    *"dat0 quit unexpectedly — send a report? [optional note] [Send] [Don't send]"*.
    **Send** ⇒ submit the staged event **with the note** via the now-healthy client,
    then delete the staging file + marker. **Don't** ⇒ delete both, submit nothing.
  - marker survived but no staged context (a non-panic abnormal exit — SIGKILL,
    native segfault) ⇒ offer a minimal "dat0 exited abnormally" report through the
    same dialog.
  - If `crash_submission_enabled` is `false` ⇒ silently delete the staged data +
    marker, no dialog, no submission.
- Reuses P10b's dialog infrastructure (`window.open_dialog`, `Root::render_dialog_layer`,
  the `Fn`-builder + `Rc`-store pattern from `workspace_in_use_modal.rs`).

**A2 — "Report a bug".** An always-available Help-menu action (and/or an About-box
link) opening the same note dialog; **Send** captures a user-initiated message event
(`level = info`, tagged `report-a-bug`) with the note. No crash required. Routes through
the same live client + `before_send` redaction.

**A3 — Real DSN.** Operator sets the `GLITCHTIP_DSN_PUBLIC` repo secret (already
referenced by `ci.yml`/`heavy.yml`); `.cargo/config.toml` keeps the `invalid` stub for
local builds. No code change to DSN reading (D6). The release build embeds the real DSN
at compile time via the existing CI env wiring.

**A4 — Redaction hardening.** Extend `telemetry/redaction.rs` tests to assert the
`before_send` payload strips, for both a staged-crash event and a Report-a-bug event:
absolute paths (→ `<path>`), schema/column names, query text, source-data values, BYOK
keys, MotherDuck token, server hostname/user. This is the privacy contract from
`docs/privacy.md`; it is now load-bearing because transmission is live.

### 5.B Workstream A — Verification

- **`xtask send-test-event`.** A build-only `xtask` subcommand that fires a single
  tagged test event (`dat0 telemetry e2e <git-sha>`) through the real client +
  redaction path. The reusable trigger for both the CI gate and manual UAT.
- **Soft CI gate** (`.github/workflows/crash-e2e.yml`, `continue-on-error: true`):
  build with the real DSN, run `xtask send-test-event`, then query the GlitchTip API
  (needs `GLITCHTIP_API_TOKEN` + project-slug secrets) to assert the event arrived and
  that the stored payload shows no un-redacted PII. Soft from day one (D4) — a
  GlitchTip outage cannot redden `main`. Mirrors the `ai_live` soft-gate shape.
- **Manual UAT** (`docs/plans/2026-06-24-dat0-p10c-uat.md`): on a signed release build
  with the real DSN — (a) trigger a real panic, relaunch, confirm the dialog, **Send**
  with a note, verify the event + note + redaction in the GlitchTip UI; (b) exercise
  "Report a bug"; (c) confirm opt-out suppresses all submission. The authoritative
  proof of the exit gate.

### 5.C Workstream B — D-029

1. **Change-gate persist-on-render.** The Settings panel currently persists
   (`set` → `SettingsStore::save`, fsync + parent-dir fsync) on **every** render tick,
   even unchanged. Cache the last-persisted `String`s (and the budget value) on the
   panel; call the setter only when the value actually changed — or move persistence
   to the input `on_change`/blur hook. Correctness is unchanged (last-write-wins);
   this removes the per-frame double-fsync.
2. **Cleanup trio** (zero-risk subtractions):
   - Delete `SettingsView` (struct + `Render` impl) and the dead
     `SettingsSection::render()` trait method + its 9 placeholder impls. `SettingsPanel`
     superseded them in P10b T4.
   - i18n the two hardcoded `.placeholder("Name")`/`("Email")` strings in `panel.rs`
     (new `settings.profile.name_placeholder` / `…email_placeholder` keys).
   - Drop the orphan `settings.update.auto_check` i18n key + the stale comment that
     references it (duplicates `settings.updates.toggle`).
3. **i18n-check correction.** Fix the planning-doc claim that `scripts/i18n-check.sh`
   "fails on missing keys" (it is warn-only, `exit 0`, and does not resolve referenced
   keys). Add a referenced-key → `en.json` resolution pass that **warns** (still
   `exit 0`, D5) on any `t("…")` key absent from the catalog.

### 5.D Docs / deferrals / operator

- **`docs/release-runbook.md`** — add a GlitchTip ops section: instance provisioning
  pointer, DSN issue/rotation, the two new CI secrets (`GLITCHTIP_DSN_PUBLIC`,
  `GLITCHTIP_API_TOKEN`) + project slug, Postgres backup + basic uptime monitoring
  (spec R11 degradation note).
- **Deferrals:** close **D-029** (commit ref at merge). Add dated notes to **D-013**
  (perf-gate runner — still gated on Mac mini) and the beta-channel line (still gated
  on testers) recording that P10c left them deferred and why.
- **Operator actions (pre-merge / pre-real-e2e):** provision is done; set the two CI
  secrets; the runbook documents them. The soft gate stays green-skipping until the
  secrets exist.

## 6. What P10c closes vs. leaves

- **Closes:** the GlitchTip half of the P10 exit criteria — "opt-in crash submission
  flipped to submit" (already wired; DSN + surfaces + proof added) and "GlitchTip
  end-to-end verified" (soft CI gate + manual UAT). Closes **D-029**.
- **Leaves (the only remaining P10-exit gaps, both pure-external):** the GPU
  perf-gate runner / merge-blocking perf budgets (**D-013**) and the beta channel
  kickoff. Both unblock only when hardware / testers exist; neither is a code task.

## 7. Risks

| Risk | Mitigation |
|---|---|
| Suppressing sentry's default panic capture in favor of staged relaunch-submit mis-wires and drops crashes | Unit-test the panic hook stages a well-formed `last-crash.json`; manual UAT confirms a real panic round-trips. Keep the staging path independent of the network transport. |
| Relaunch dialog races the crash sentinel / multi-window or fast-relaunch edge cases | Single-staging-file (last crash only) keyed by the marker; delete-after-handle is idempotent; design mirrors P7b's `lock.json`/manifest single-owner discipline. |
| Live GlitchTip e2e flakes CI | Gate is `continue-on-error` from day one (D4). Manual UAT is authoritative. |
| Redaction regression leaks PII once transmission is live | A4 hardens `before_send` tests; the soft CI gate also asserts no un-redacted PII in the stored payload. |
| Change-gating persist subtly breaks save semantics | Keep last-write-wins; add a regression test that an actual value change still persists and an unchanged render does not write. |
