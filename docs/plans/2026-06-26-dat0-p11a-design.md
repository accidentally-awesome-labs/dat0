## 1. Why this slice exists

The master spec assigns onboarding **design** to P9c and **implementation** to P11.
The design shipped in P9c-3 as a design-only deliverable (`docs/design/onboarding-v1.md`):
enriched first-run hero, a 7-panel skip-able carousel, a curated `demo.dat0` workspace,
and a README first-run section. P11a is that document made real.

P11 as a whole is "docs site + launch" — a multi-subsystem phase mixing Rust code, a
separate web repo, brand assets, and human launch coordination. Per the brainstorming
decomposition rule it splits into P11a / P11b / P11c (above). P11a is taken first
because it is the only slice that is (a) pure Rust in this repo, (b) fully designed
already, and (c) unblocked — P11b needs a new repo and a non-Rust stack, P11c is gated
on real signing keys, brand assets, and a beta cohort that do not yet exist.

## 2. Scope surprise discovered while brainstorming (drives the scope decision)

`onboarding-v1.md` states it "extends" the P3 empty-state hero and "does not duplicate"
it — assuming a working hero to enrich. Code exploration on 2026-06-26 found the hero is
a **non-functional skeleton**:

- `crates/dat0-app/src/empty_state.rs` renders placeholder copy only. The sample-data
  buttons are plain text with **no click handlers** (the doc comment says they were
  "deliberately deferred to a T7 follow-up" in P3b — the follow-up never landed). The
  recents column renders a literal `"Recents…"` string.
- `crate::sample_data::ensure_bundled_extracted` has **zero real callers** — it is
  referenced only in the skeleton and its own doc comment. There is no working
  sample-open path anywhere in the app.

The underlying **mechanisms all exist and work**, though: `file_drop.rs` handles dropped
paths, `cx.prompt_for_paths` is the file-open path (used throughout `window.rs`), the
`Recents` store already feeds the macOS menu (`Recents::with_path(cfg.join("recents.json")).list()`),
and `ensure_bundled_extracted` extracts bundled bytes. What is missing is purely the
**hero UI wiring** to those mechanisms — small, mechanical, not a from-scratch build.

**Decision (user-approved): wire + enrich in one slice.** P11a wires the real hero
(working sample buttons, recents list, Open-file button) *and* adds the first-run
enrichment (value-prop band, demo CTA, carousel). Rejected: splitting base-wiring into
its own pre-slice (cleaner blast radius but two cycles for cohesive work); minimal
wiring (leaves recents as a visible placeholder — onboarding ships a half-built hero).

## 3. Locked decisions

| # | Decision | Rejected alternative | Why |
|---|----------|----------------------|-----|
| **P1** | **Wire + enrich in one slice.** P11a makes the hero functional (samples/recents/open) and adds the first-run band + demo CTA + carousel together. | Split base-wiring into P11a-0; or wire only onboarding-touched buttons. | Onboarding needs working buttons regardless; the wiring is small because the mechanisms already exist. One cohesive slice. |
| **P2** | **`first_run_done` lives in settings**, a new `bool` on `Settings` (`settings/schema.rs`); `schema_version` 1→2. `#[serde(default)]` (false) means an absent field reads as first-run-pending. | A field in `session.json` (per-workspace). | Onboarding completion is per-install, not per-workspace — exactly the design's recommendation (`onboarding-v1.md` §3). |
| **P3** | **Upgrade default = false.** Existing installs (no field yet) read `first_run_done == false`, so anyone updating to the v1 build sees the enriched hero + auto-tour once. No explicit migration code — the serde default does it. | A migration that sets `true` for existing installs so only fresh installs auto-tour. | Simplest; current users have never seen onboarding; beta testers re-seeing it once is acceptable. |
| **P4** | **Tour art = annotated real screenshots**, captured from the running app, bundled as PNGs. Code is built against placeholder PNGs; real captures swap in before ship. | GPUI-drawn panels (lowest polish); commissioned illustrations (needs a designer — external blocker). | Authentic to the actual UI, no external dependency, achievable from this repo. Cost is a capture pass + re-shoot on UI drift (filed as a deferral). |
| **P5** | **`demo.dat0` is authored + round-trip-verified in P11a.** Build the Open-demo code path *and* author the real curated artifact via in-app export, bundle it, and verify lineage survives. | Code path now + artifact as a slippable gated sub-task; or defer `demo.dat0` and feature Chinook raw-open as the CTA. | Full design intent (D4 — the strongest single demo). Accepts the manual-authoring step and the round-trip risk as in-scope work; the round-trip test guards D-025. |
| **P6** | **Carousel is a self-contained modal** built on the existing gpui-component Dialog/Modal surface (templates: `about/mod.rs`, `workspace_in_use_modal.rs`, `live_refresh_dialog.rs`). | A bespoke overlay widget; coach-marks anchored to live UI. | Reuses a proven, already-vendored surface; matches `onboarding-v1.md` D2 (decoupled from live UI). |

## 4. Components

### 4.1 `first_run_done` flag (`settings/schema.rs`)

Add to `Settings`:

```rust
/// Whether the first-run onboarding (enriched hero + auto-tour) has been
/// completed or skipped. Per-install, not per-workspace. Set true the first
/// time the carousel is finished or skipped. Absent in pre-v2 settings →
/// false (upgraders see the tour once).
#[serde(default)]
pub first_run_done: bool,
```

Bump `schema_version` default 1→2. Add a `set_first_run_done(store, bool)` helper
mirroring the existing `set_memory_budget_mb` / `set_log_level` atomic-write pattern.
No bespoke migration — `#[serde(default)]` covers the absent-field case (P3).

### 4.2 First-run state machine (consumed at `window.rs:~5849`)

The empty-state branch currently builds `EmptyState::new(recents_empty).render(cx)`.
It gains the first-run dimension:

```
empty session (no open tabs AND no recents)?
  yes → first_run_done == false ?
          yes → ENRICHED hero (band + demo CTA + demoted samples)
                + auto-open carousel exactly once
          no  → PLAIN wired hero (working samples + recents, no band, no autopopup)
  no  → normal workspace
```

The selection logic is pure (inputs: `recents_empty`, `first_run_done`, has-open-tabs)
→ unit-testable without GPUI. `EmptyState` grows a `first_run_done: bool` field (or a
small `HeroMode { Enriched, Plain }` enum) so the render branch is data-driven.

### 4.3 Hero wiring (base — both modes)

- **Sample buttons** (`sample_data::entries()`): `.on_click` → `ensure_bundled_extracted`
  into the platform config/scratch dir → open via the same path drop/picker use →
  record in `Recents`. (Iris CSV, Chinook SQLite — bundled; NYC taxi Parquet keeps its
  existing remote-fetch + retry-banner path via `sample_data::fetch_failed_banner`.)
- **Recents column** (when `recents_empty == false`): render `Recents::list()` entries,
  each `.on_click` → reopen that path.
- **`[Open file…]` button**: `.on_click` → `cx.prompt_for_paths` (same options the menu
  uses) — explicit affordance beside the existing drop-zone text.

### 4.4 Enriched band (first-run only)

Above the existing two-column hero, render: the `dat0` headline, tagline ("Explore data
at native speed — local and private."), a top-right `[Take a tour ›]`, and a featured
"Try the demo workspace" card with `[▶ Open demo.dat0]`. The three raw samples are
demoted beneath the featured CTA (rendered exactly as the base hero does — this band
only re-orders them). Renders **only** when `first_run_done == false`; otherwise the
plain wired hero shows.

### 4.5 Carousel widget

Self-contained modal, 7 panels per `onboarding-v1.md` §5. Each panel = `{ image, headline,
body }`. Chrome: `[Skip]` bottom-left (always; dismisses + sets `first_run_done`), center
dot pager, `[‹ Back]` from panel 2, `[Next ›]` bottom-right → `[Get started]` on panel 7
(closes → lands on hero). Auto-opens once when the state machine selects the enriched
branch; finishing or skipping calls `set_first_run_done(true)`. Reachable forever after
via `[Take a tour ›]`, a macOS **Help › Take a tour** menu item (`menu_macos.rs`), and a
**command-palette action** (cross-platform; the only entry point on Linux, which has no
menu bar yet).

Copy invariants (carry verbatim, `onboarding-v1.md` §5): panel 4 — AI-drafted SQL is
reviewed before it runs; panel 7 — AI is off until a key is added and data stays local.

### 4.6 `demo.dat0` (featured CTA)

- **Authoring (manual, during execution):** inside dat0 → drop Chinook → build the
  "Revenue by genre" bar chart + a small projection pipeline + a "Top customers" SQL tab
  → **in-app Export `.dat0`** (NOT the cold CLI exporter — D-025: cold export flattens
  derived-origin lineage; in-app preserves it) → check the artifact into
  `crates/dat0-app/assets/demo.dat0` (~1–2 MB) → bundle via `include_bytes!` (mirrors
  `chinook.sqlite`).
- **Open path:** `[▶ Open demo.dat0]` extracts the bundled bytes to a temp/scratch path
  and opens it as a workspace, landing with the **saved-chart tab focused**; the SQL tab
  is pre-filled but **not** auto-run (never-auto-run discipline).
- **Verification:** an integration test loads the bundled `demo.dat0` and asserts the
  saved chart's lineage and the pipeline survive the round-trip (guards D-025).

### 4.7 Tour art pipeline

Seven annotated screenshots, bundled PNGs under `crates/dat0-app/assets/onboarding/`.
The carousel code references them by stable filename; P11a ships **placeholder** PNGs so
the code compiles and renders, and a capture task produces the real annotated shots that
swap in before ship. (Re-capture on UI drift is a deferral, §7.)

### 4.8 README first-run section

Add a "Quick start / First run" section to `README.md` (`onboarding-v1.md` §7): install →
launch → "Try the demo workspace" (or drop a file); one enriched-hero screenshot; a
3-bullet highlight (native-fast grid · SQL + charts · bring-your-own AI); a privacy line
(local-first; AI off until you add a key); links to AI BYOK setup and the privacy doc.
(The privacy doc itself is finalized in P11b/P11c, not here — link target may be a stub
until then.)

## 5. i18n / privacy invariants

All new user-facing strings go through the `t("…")` wrapper with new keys, English-only
values at v1 (structured for later locales — `onboarding-v1.md` §9). The P10c i18n-check
(referenced-key resolution, warn-only) must stay green. Localized onboarding copy is a
deferral.

## 6. Testing (TDD + subagent-driven-development, the standard dat0 flow)

- **State-machine selection** — pure unit tests over (`recents_empty`, `first_run_done`,
  has-open-tabs) → correct hero mode + auto-open decision.
- **Settings v1→v2** — round-trip test: pre-v2 JSON (no `first_run_done`) deserializes to
  `false`; `set_first_run_done(true)` persists and reloads.
- **Hero wiring** — render smoke test for both modes; sample-extract test reusing the
  existing `ensure_bundled_extracted_is_idempotent` pattern.
- **Carousel** — construct + pager-bounds unit tests (Skip/Back/Next transitions, panel-7
  "Get started", finish/skip → flag set).
- **`demo.dat0`** — bundled-asset round-trip integration test (lineage + pipeline intact).

## 7. Deferrals / non-goals (each stays where it is)

- **Docs site `dat0.dev`** → **P11b** (separate `dat0-site` repo, Astro+Starlight).
- **v1.0.0 tag · repo private→public flip · prod minisign-key swap (P10a-2 pre-release
  ops) · beta cohort · Discord public · brand assets · launch posts** → **P11c.**
- **`demo.dat0` refresh automation** — re-authored by hand when the `.dat0` format or the
  showcased features drift; a build-time freshness check is a later-phase candidate
  (carried from `onboarding-v1.md` §9).
- **Tour-art re-capture on UI drift** — manual for v1.
- **Localized onboarding copy** — English-only at v1, keyed for later locales.
- **Spotlight / coach-mark tour, inline contextual hints** — rejected in
  `onboarding-v1.md` D2/§9; revisitable post-v1 on telemetry signal.

## 8. Acceptance checks (from `onboarding-v1.md` §10)

- First launch (empty session, `first_run_done == false`) shows the enriched hero **and**
  auto-opens the carousel exactly once.
- Skipping or finishing the carousel sets `first_run_done`; later launches show the plain
  wired hero with no auto-popup; `[Take a tour]` / Help / palette still open it.
- `[▶ Open demo.dat0]` opens the curated workspace with the saved chart's lineage and the
  pipeline intact (round-trip verified).
- The three raw samples load (sample buttons now actually work — closing the P3b debt).
