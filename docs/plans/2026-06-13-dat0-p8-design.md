## Goal

Make a dat0 workspace a **shareable, replayable artifact**. Today a workspace lives in a
`.dat0/` *directory* (P7 — the git-style working home). P8 adds the `.dat0` *file* — a
single zip that packages a workspace's data + derivation recipe + saved queries + view
state so it can be:

1. **Exported** from a live workspace (`dat0 export`, or in-app "Export as Package").
2. **Inspected** read-only without unpacking (in-app Inspect mode; `dat0 inspect`).
3. **Unpacked** back into an editable workspace, state-equivalent to the source.
4. **Replayed on a new source** — rebind the package's source file(s) to fresh data with a
   compatible schema, re-run the whole derivation recipe, get deterministic new derived
   tables.
5. **Diffed** — `dat0 diff a.dat0 b.dat0` produces structured schema / lineage / query /
   row-count deltas.

The format spec is published as a ratified document (`docs/dat0-format-v1.md`) with a
manifest JSON Schema, so the format is stable, versioned, and cross-language-readable
(Parquet + JSON — no proprietary blobs).

### The `.dat0` file vs the `.dat0/` directory

| | `.dat0/` **directory** (P7) | `.dat0` **file** (P8) |
|---|---|---|
| Analogy | `.git/` working repo | a bundle / archive snapshot |
| Form | folder on disk, mutated in place | single zip, immutable once written |
| Contains | live `workspace.duckdb`, `session.json`, lock, manifest | Parquet data cache + recipe/queries/views/sources JSON + manifest |
| Purpose | the workspace you edit | the artifact you share / archive / replay / diff |

These are distinct concepts that happen to share the `.dat0` name (intentional brand
consistency, like `.git`). The package manifest carries `kind: "package"` to disambiguate
from the workspace manifest's implicit `kind: "workspace"`.

## Locked decisions

| # | Decision | Rationale |
|---|----------|-----------|
| **D1** | **Combined P8a+P8b design, split at plan time.** | The format can't be ratified without designing its consumers (writer/reader/replay/diff). One coherent design; `writing-plans` carves the P8a doc deliverable from the P8b implementation tasks. |
| **D2** | **Parquet per table** inside the zip (`data/<table>.parquet`). | Open columnar format → cross-language Python reader, per-table diff, and compression all fall out for free. DuckDB reads/writes it natively (`COPY TO/FROM PARQUET`), so unpack/inspect re-materialize trivially. Rejected: embedded `workspace.duckdb` (opaque, storage-version-locked, no per-table diff); hybrid both (≈2× size, drift risk). |
| **D3** | **All tables materialized; `recipe.json` is canonical, Parquet is a regenerable cache.** | One principle satisfies all four hard exit criteria: Inspect reads any table's Parquet with no engine replay; diff compares cheap cached schema/row-count; round-trip is trivially empty; replay ignores the cache and re-runs the recipe. Rejected: base-only (Inspect needs an embedded engine, diff must replay); lite/full toggle (doubles the format surface — every reader/diff/Inspect path forks). |
| **D4** | **Structural / referenced-columns replay compatibility.** | Require only the columns the recipe references, by name, with type-compatible values; ignore extras; ordering irrelevant. Handles real source drift ("next month's CSV added a column"). Mismatch on a referenced column → hard error with a schema-diff. Rejected: strict exact-match (brittle — any unrelated column change rejects); permissive+coerce (silent wrong results corrupt derived tables). |
| **D5** | **Fill in the existing `dat0-format` stub crate (pure, GPUI-free); CLI is a front-door on the existing `dat0` binary.** | `dat0-format` already exists as a one-line stub in the workspace. The GUI app binary is *already* named `dat0`, and the spec command is literally `dat0 diff` — so the CLI is a subcommand front-door on that same binary (parse subcommand before GPUI init → headless), not a separate binary. One artifact to build/sign/distribute. All logic lives in `dat0-format` so CI/tests exercise it headless. |
| **D6** | **Inspect mode = the existing workspace shell, opened read-only.** | Query the package's Parquet in place via `read_parquet` views (no import), present the existing Catalog / DataGrid / Inspector / lineage-chain UI behind a `read_only` flag that gates every mutation/write-SQL action. Maximal reuse of P3–P7; familiar UX. Rejected: dedicated viewer (duplicates UI, re-implements P6b lineage); CLI-only (guts the headline read-only-browse feature). |
| **D7** | **`dat0 diff` = four dimensions; human-readable text default, `--json` flag.** | Spec-mandated dimensions: schema diff, lineage diff, query diff, row-count delta. Text for humans, JSON for CI/automation. Identical packages → empty diff, exit 0. |
| **D8** | **`format_version: 1` integer; semantic compat — dat0 1.x always reads format 1.x.** | Mirrors the P7a workspace-manifest convention (`format_version: u32`). Forward-compat: unknown fields ignored (serde), missing optionals default. Major-version mismatch → refuse with a clear message. |
| **D9** | **Package = portable workspace content only.** Included: recipe, data, sources, queries, views. **Excluded: credentials (MotherDuck token never travels), ephemeral window/UI state (scroll, dock sizes, tab order), app settings.** | A shared artifact must never leak secrets or carry machine-specific UI cruft. Attached-DB references recorded informationally in `sources.json`, never their secrets. |
| **D10** | **Cell-edit/projection/filter overlays stay in `views.json` (recipe); `data/*.parquet` is the *base* materialization.** | Consistent with the P6a finding that edits are display overlays (`compile_view_sql` → `SELECT * REPLACE (CASE…)`), not base mutations. The in-app reader re-applies overlays via the existing `compile_view_sql`; CLI diff compares base data + recipe JSON. |
| **D11** | **Replay engine = topological recipe re-execution, built in `dat0-format`.** | This is exactly the cross-table refresh cascade deferred as **D-023** (from P7c). Building it engine-level in `dat0-format` lets both the package replayer and a future in-app refresh-cascade consume it. P8b's replay engine **addresses D-023** (note in the deferral register at plan time). |
| **D12** | **No `session.json` schema bump.** Package read/write is a new artifact path; it does not change the live workspace's persisted shape (stays session v8). | Packages are produced *from* and unpacked *into* workspaces, but the in-memory→on-disk workspace contract is untouched. |

## Non-goals (P8)

Deliberately **out of scope**, to keep the phase to ~4 weeks:

- **Encryption / signing** of packages. (No secrets travel — D9 — so unsigned is safe for v1. Signing is a P10/distribution concern.)
- **Python reader implementation.** The format is *designed* to be cross-language-readable (Parquet + self-describing tagged JSON, per the PD-014 wire-format note), but no Python reader ships in P8.
- **Delta / incremental packages, package merge, three-way diff.** `dat0 diff` is a two-package structural compare only.
- **`dat0.dev/format/v1` site mirror wire-up.** The spec doc is committed and reachable on GitHub; the public site mirror is a placeholder, finalized in P11 (per master spec).

## Architecture

### Crate / component graph

```
dat0-format  (fill in stub — PURE, no GPUI)
  ├── model::{PackageManifest, Recipe, Sources, Queries, Views}   serde types + JSON Schemas
  ├── writer::Writer          workspace state → .dat0 zip
  ├── reader::Reader          .dat0 zip → in-memory model + Parquet handles
  ├── replay::ReplayEngine    rebind source → topological recipe re-exec (addresses D-023)
  └── diff::DiffEngine        two packages → structured Diff
        depends on: dat0-engine (DuckDB COPY TO/FROM PARQUET, query exec), serde, zip, jsonschema

dat0  (the existing dat0-app binary)
  └── main front-door: if argv[1] ∈ {export,inspect,unpack,replay,diff} → CLI (headless, → dat0-format)
                       else → launch GUI
  └── GUI actions: Export Package, Open Package (Inspect), Unpack to Workspace, Replay
        depends on: dat0-format
```

`dat0-format → dat0-engine` is acyclic (the engine has no knowledge of the format). The
CLI front-door lives in `dat0-app::main` but every operation delegates to `dat0-format`,
so the format logic is fully testable without GPUI.

### Package layout (the `.dat0` zip)

```
analysis.dat0   (zip; deflate for JSON; Parquet stored without recompression)
├── manifest.json     identity, format_version, kind="package", table_count, checksums
├── recipe.json       CANONICAL — tables (base|derived), schemas, row-counts, derivation SQL, parent edges
├── sources.json      per base table: source id, import SQL, schema fingerprint, content hash
├── queries.json      saved queries (P5b)
├── views.json        per-table projection / filter / sort / cell-edit overlays (P4 / P6a)
└── data/
    ├── sales.parquet      base table — snapshot at export
    └── monthly.parquet    derived table — regenerable cache of the recipe output
```

### Data model (the spec's ratified shapes)

**`manifest.json`**
```jsonc
{
  "format_version": 1,
  "kind": "package",
  "dat0_version": "0.x.y",
  "package_id": "<uuid-v7>",
  "workspace_id": "<uuid-v7>",   // origin workspace, for provenance
  "created_at": "2026-06-13T12:00:00Z",
  "table_count": 2,
  "checksums": { "recipe.json": "sha256:…", "data/sales.parquet": "sha256:…" }
}
```

**`recipe.json`** — canonical truth; data Parquet is its cache.
```jsonc
{
  "tables": [
    { "id": "t_sales", "name": "sales", "origin": "base",
      "schema": [ { "name": "id", "type": "BIGINT" }, … ],
      "row_count": 10342, "data": "data/sales.parquet",
      "source_ref": "src_sales" },
    { "id": "t_monthly", "name": "monthly", "origin": "derived",
      "schema": [ … ], "row_count": 12, "data": "data/monthly.parquet",
      "derivation": { "sql": "SELECT month, sum(total) … FROM sales GROUP BY 1",
                      "parents": ["t_sales"] } }
  ]
}
```
Parent edges are stored explicitly (`parents`) AND validated against P6b's
`referenced_tables(sql)` AST-walk at write time — a mismatch is a writer bug caught in CI.

**`sources.json`** — what replay rebinds.
```jsonc
{
  "sources": [
    { "id": "src_sales", "logical_name": "sales.csv",
      "original_uri": "/Users/…/sales.csv",
      "import_sql": "CREATE TABLE sales AS SELECT * FROM read_csv('{src}', header=true)",
      "schema_fingerprint": [ { "name": "id", "type": "BIGINT" }, … ],
      "content_hash": "sha256:…", "row_count": 10342 }
  ]
}
```
`{src}` is the rebind placeholder. `schema_fingerprint` drives the structural compat
check (D4). `content_hash` lets replay detect "same source" (→ identical output expected).

**`queries.json`** — `[{ "name", "sql", "created_at" }]` (P5b saved queries).

**`views.json`** — per-table `{ table_id → ViewState }` carrying the P4 projection
(column order / rename / hide), filters, sorts, and cell-edit overlays. Reapplied at read
time via the existing `compile_view_sql` (D10).

### Replay flow (the killer feature)

```
dat0 replay analysis.dat0 --source new_sales.csv  [-o updated.dat0]
  1. Reader loads manifest + recipe + sources.
  2. Bind: match --source to a source by logical_name (or --source src_id=path for multi-source).
  3. Compat check (D4): fingerprint new source; require recipe-referenced columns present
     + type-compatible by name. Mismatch → hard error printing the schema-diff. Exit ≠ 0.
  4. Re-import: run the source's import_sql with {src} = new path → fresh base table.
  5. Topological re-exec (D11 / addresses D-023): walk the recipe DAG in dependency order,
     re-run each derived table's derivation SQL → fresh derived tables.
  6. Re-materialize Parquet (cache) + recompute schemas/row-counts + write updated package
     (or open in a workspace if invoked from the GUI).
```
Determinism: same source (matching `content_hash`) → byte-identical derived Parquet given
the same dat0/DuckDB version. A compatible-but-changed source → new rows, same schema
shape. Both are covered by tests.

### Inspect mode (in-app, read-only)

```
Open Package (file picker, *.dat0)
  → Reader extracts JSON to a temp dir; data/*.parquet stay in place / extracted read-only
  → engine registers each table as a read_parquet VIEW (no CTAS import — fast open)
  → WorkspaceShell mounts in read_only = true:
      • Catalog tree, DataGrid, Inspector profiling, P6b lineage chain — all reused as-is
      • compile_view_sql re-applies views.json overlays so the grid shows the edited view
      • every mutation/write action (cell edit, transform apply, Save-as-Table, write-SQL)
        is gated behind read_only and disabled/hidden
      • a prominent "Unpack to edit" button → real editable workspace (P7 promotion path)
```
The `read_only` flag threads through the existing action sites (the same surfaces P4b/P4c
wired). Read-SQL in the SQL Console is allowed (it can't mutate read-only Parquet views);
DDL/DML is rejected by the read-only engine handle.

### `dat0 diff`

```
dat0 diff a.dat0 b.dat0  [--json]
  • schema diff   — per matched table: added / removed / retyped columns
  • lineage diff  — added / removed table nodes + derivation-edge changes
  • query diff    — added / removed / changed saved queries (by name, then sql)
  • row-count delta — per matched table: a.rows → b.rows
Tables matched by name. Text output groups by dimension; --json emits a structured object.
Identical packages → no output, exit 0. Differences → exit 1 (scriptable).
```
Diff operates on the JSON model + Parquet metadata (row counts from Parquet footers) — it
never has to replay, because materialized state is present (D3).

## Versioning & compatibility

- `format_version` is a single integer in the manifest. **Policy: dat0 1.x always reads
  format 1.x.** Forward-compat within a major: unknown JSON fields are ignored (serde),
  missing optional fields take defaults. A package whose `format_version` major exceeds the
  running dat0's supported major → refuse to open with a clear, actionable message.
- The format spec doc `docs/dat0-format-v1.md` is the normative reference. A published
  **manifest JSON Schema** (`docs/schemas/dat0-manifest-v1.schema.json`) validates against
  test fixtures in CI (spec exit criterion).
- `dat0.dev/format/v1` mirror: placeholder now, wired up in P11 with the site.

## Testing & exit criteria

Maps directly to the master-spec P8a + P8b exits:

| Test | Asserts |
|------|---------|
| Manifest JSON Schema validates fixtures | P8a: schema published + correct |
| Round-trip empty diff (headless CLI) | `export → unpack → diff` produces no deltas |
| Replay determinism — identical source | same `content_hash` source → identical derived Parquet |
| Replay — compatible-but-changed source | new rows, same schema; derived tables recomputed |
| Replay — incompatible source | hard error printing the schema-diff; exit ≠ 0 |
| Parquet type fidelity | DECIMAL / NULL / temporal types survive write→read (guards the P6a `Decimal128`/null gotchas) |
| Inspect read-only gating | every mutation/write action disabled under `read_only`; read-SQL allowed |
| `dat0 diff` structured output | each of the 4 dimensions reports correctly; `--json` parses; identical → empty/exit 0 |
| 1M-row export/import bench | contributed Criterion/CLI bench; advisory (hard perf gates lock at P10) |

## Open implementation notes (for `writing-plans`, not blockers)

- **`compile_view_sql` location.** It currently lives in `dat0-app` (`render.rs`). In-app
  Inspect reuses it natively (D10). The CLI `diff` does *not* need it (compares base data +
  recipe). If a future need arises to apply overlays headlessly, that function would move
  to `dat0-engine`/`dat0-format` — out of scope for P8.
- **Front-door arg parsing.** Branch on `argv[1] ∈ {export,inspect,unpack,replay,diff}`
  *before* any GPUI/tokio-GUI init, so headless CLI never spins the window loop. Reuse the
  P4b lesson: the tokio runtime must be entered for any engine work (`runtime.enter()`).
- **T0 spikes worth gating** (decide in the plan): DuckDB `COPY TO PARQUET` round-trip type
  fidelity for the P6a-gotcha types; `read_parquet`-view read-only Inspect open path; the
  argv front-door dispatch not disturbing the existing GUI launch.
