# dat0 P8 T9 — Manual UAT checklist (Inspect / Export / Unpack / Replay)

Headless CI cannot click native panels or GUI menus, so the GPUI side of P8 T9
is build- and clippy-verified but NOT exercised end-to-end. This checklist
captures the manual passes a human must run on macOS (and, where applicable,
Linux). It **joins the standing P4b / P4c / P5b / P5c / P6a UAT backlog** — none
of that earlier manual UAT has been run yet either.

The engine core (`package::inspect::open_readonly`) and the CLI cores ARE
covered by automated tests (`tests/inspect_open.rs`, `tests/cli_roundtrip.rs`);
this doc covers only what a test harness cannot reach.

## Pre-req

- A built `dat0.app` (release or debug) on macOS.
- A scratch workspace with at least one base table (drop a CSV) and ideally one
  derived table (run a `CREATE TABLE … AS SELECT …` in the SQL console, or a
  Save-as-Table).

## 1. Export as .dat0 Package (File → Export as .dat0 Package…)

1. Open a workspace / scratch session with a base table + a derived table.
2. File → **Export as .dat0 Package…** → pick a destination, name it
   `proj.dat0`.
3. Expect: an info banner "Package exported" with the output path.
4. Verify on disk: `dat0 inspect proj.dat0` lists the expected tables, row
   counts, and (for the derived table) a lineage edge / `derived` kind.
   - NOTE: derived-origin is only tracked in the LIVE engine's in-memory map.
     Exporting from a live session preserves it; exporting via the CLI (which
     reopens the workspace) re-classifies it Base — see `cli_roundtrip.rs`
     FINDING. The GUI export goes through the LIVE session, so derived lineage
     should survive here.
5. Negative: with NO workspace focused (e.g. only an empty/scratch app window),
   Export should surface the "No workspace to export" warning banner.

## 2. Open Package read-only / refuses edits (File → Open .dat0 Package…)

1. File → **Open .dat0 Package…** → pick `proj.dat0`.
2. Expect: a NEW window opens showing the package's tables (the tabs from the
   package's views) populated from the parquet (read-only Inspect mode).
3. Try a **cell edit** in the grid (double-click a cell, type, commit). Expect:
   the edit is refused (no mutation; the read-only gate blocks it).
4. Open the SQL console and run a **non-SELECT** (e.g.
   `INSERT INTO <table> VALUES (…)` or `CREATE TABLE x AS …`). Expect: the run
   is blocked by the read-only gate (no execution).
5. Run a **SELECT** in the console. Expect: it works (read-only allows reads).
6. Sanity: the underlying tables are `read_parquet` VIEWS, so even if a path
   bypassed the app gate, the engine itself would reject DML on a view.

## 3. Unpack to an editable workspace (File → Unpack .dat0 Package…)

1. File → **Unpack .dat0 Package…** → pick `proj.dat0` → pick a target folder.
2. Expect: an info banner "Package unpacked" with the target path, AND the
   unpacked workspace opens as a NORMAL (edit-enabled) window.
3. In the unpacked window, make a **cell edit** — expect it to SUCCEED (this is
   a real editable copy, not read-only).
4. Verify on disk: `<target>/.dat0/workspace.duckdb` + `session.json` exist.

## 4. Replay against a fresh source (File → Replay .dat0 Package…)

1. Have a NEW version of one source file ready (e.g. an updated `sales.csv` with
   more rows), matching the package's first source's logical name.
2. File → **Replay .dat0 Package…** → pick `proj.dat0` → pick the new source
   file → pick an output `replayed.dat0`.
3. Expect: an info banner "Package replayed" with the output path.
4. Verify: `dat0 inspect replayed.dat0` shows the derived tables recomputed
   against the new source (updated row counts), and
   `dat0 diff proj.dat0 replayed.dat0` reports the row-count differences.
   - NOTE: the GUI replay binds the picked file to the package's FIRST source
     only (single-source convenience). Multi-source replay remains available via
     `dat0 replay --source name=path …`.

## 5. CLI smoke (headless — already covered by tests, re-confirm by hand once)

```
dat0 export <workspace> -o /tmp/p.dat0
dat0 inspect /tmp/p.dat0            # text tree of tables/lineage/queries
dat0 inspect /tmp/p.dat0 --json     # JSON report
dat0 unpack /tmp/p.dat0 /tmp/unpacked
dat0 replay /tmp/p.dat0 --source <logical>=<newfile> -o /tmp/r.dat0
dat0 diff /tmp/p.dat0 /tmp/r.dat0   # exit 0 if equal, 1 if differences, 2 on error
```

## Known non-blocking gaps (for the record)

- **No "Unpack to edit" button in the read-only Inspect header.** Deliberately
  skipped in T9: it would require storing the source `.dat0` path on the shell +
  a new view-scoped action + render wiring. Unpack-to-edit is fully available
  from File → Unpack .dat0 Package…. Candidate followup if a one-click affordance
  is wanted.
- **No visible "read-only" badge** in the Inspect window chrome. The state is
  enforced (edits refuse) but not labelled. Candidate followup.
- The Inspect scratch dir (extracted parquet + view-backing DB) lives under the
  app state dir (`<state>/inspect/<uuid>/`) and is intentionally retained for the
  window's lifetime (the views read its parquet). It is best-effort removed on
  open FAILURE but NOT garbage-collected on window close — a future cleanup pass
  could prune `<state>/inspect/` on launch (mirrors the orphan scratch scan).
