# P9b — MotherDuck: close the gaps — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the residual master-spec P9b items left after P5c — a distinct catalog "Cloud" group, a "Test connection" affordance, and a token-never-logged guard — without touching the proven engine/keychain/routing core.

**Architecture:** Pure-first. The Cloud grouping is a classification rule on engine-provided `TableOrigin::Attached { source }` (`source.starts_with("md:")`) entirely inside `catalog/tree.rs`. The Test-connection button reuses the existing `precheck` → `run_connect` path (workspace-mode ATTACH is idempotent), surfacing a transient pass/fail message held on `ConnectionManager`. No engine-crate change, no settings/session schema bump.

**Tech Stack:** Rust, GPUI (free-function panels via `cx.listener`), DuckDB engine (`dat0-engine`), `dat0-keychain`, `dat0-i18n` (single `en.json`), TOML settings persistence, tokio for async engine bridges.

**Spec:** `docs/plans/2026-06-15-dat0-p9b-design.md`

**Branch:** `p9b-design` (already created off `main` `4aeb1a0`; the design doc is committed there). Execute tasks on this branch.

**Conventions (verified against the repo):**
- `dat0_i18n::t(key) -> String` returns the key itself if missing (`crates/dat0-i18n/src/lib.rs:18`); a single locale file `crates/dat0-i18n/src/strings/en.json`.
- Gate per task: `cargo test -p <crate> <filter>` → `cargo clippy --workspace --all-targets -- -D warnings` → `cargo fmt --all`. The `scripts/i18n-check.sh` gate is warn-only (`exit 0`).
- MotherDuck attach records `TableOrigin::Attached { alias: <db>, source: "md:" }` (`crates/dat0-engine/src/duckdb_engine.rs:721-730`); SQLite records `source: <path>` (`:769-778`).

```rust
pub fn render_catalog(
    tree: &crate::catalog::CatalogTree,
    cx: &mut Context<WorkspaceShell>,
) -> gpui::AnyElement {
    // (display label, stable id, nodes).
    let sections: [(String, &str, &Vec<crate::catalog::CatalogNode>); 4] = [
        ("Sources".to_string(), "Sources", &tree.sources),
        (dat0_i18n::t("catalog.cloud"), "Cloud", &tree.cloud),
        ("Tables".to_string(), "Tables", &tree.tables),
        ("Derived".to_string(), "Derived", &tree.derived),
    ];

    let mut root = div()
        .flex()
        .flex_col()
        .gap_2()
        .p_2()
        .child(div().child(SharedString::from(dat0_i18n::t("catalog.title"))));

    for (label, id, nodes) in &sections {
        let mut section = div()
            .flex()
            .flex_col()
            .gap_1()
            .child(div().child(SharedString::from(section_label(label, nodes.len()))));
        for node in nodes.iter() {
            section = section.child(catalog_row(id, &node.name, cx));
        }
        root = root.child(section);
    }

    root.into_any_element()
}
```

Note: `label` binds as `&String` (coerces to `&str` for `section_label`); `id` binds as `&&str`, and `catalog_row(id, ...)` receives it where the parameter is `&str` — the existing signature `fn catalog_row(section: &str, ...)` accepts `*id`. If the compiler rejects `id` directly, change the call to `catalog_row(id, &node.name, cx)` → `catalog_row(*id, &node.name, cx)`.

            "token leaked into ConnectionManager Debug"
        );

        // Guard sanity: the sentinel IS retrievable from the store, so this
        // test would catch a real leak rather than passing trivially.
        assert_eq!(store.get().unwrap().as_deref(), Some(sentinel));
    }

```rust
    /// Spawn the async MotherDuck "Test connection" probe. Identical engine
    /// bridge to [`spawn_md_connect`] (idempotent workspace-mode ATTACH with the
    /// stored token), but additionally records a transient pass/fail message via
    /// `set_md_test_result` so the panel can confirm the probe ran — the status
    /// pill alone cannot signal "still OK" when already Connected. The token is
    /// moved straight into `run_connect` and never logged.
    ///
    /// [`spawn_md_connect`]: Self::spawn_md_connect
    fn spawn_md_test(&mut self, token: String, cx: &mut Context<Self>) {
        let engine = self.engine();
        let engine_for_list = engine.clone();
        let ws_weak = cx.entity().downgrade();
        tokio::spawn(async move {
            let status = crate::connections::connect::run_connect(engine, token).await;
            let connected = matches!(status, crate::connections::ConnectionStatus::Connected);
            let message = crate::connections::connect::test_result_message(&status);
            let dbs = if connected {
                crate::connections::connect::list_databases(engine_for_list).await
            } else {
                Vec::new()
            };
            if let Some(dispatcher) = crate::window_registry::dispatcher() {
                let _ = dispatcher.dispatch(move |app: &mut gpui::App| {
                    if let Some(ws) = ws_weak.upgrade() {
                        ws.update(app, |ws, cx| {
                            ws.connections.set_md_status(status.clone());
                            if connected {
                                ws.connections.set_md_databases(dbs.clone());
                                // Persist the md attachment (idempotent) so a
                                // recover re-attaches it — matches spawn_md_connect.
                                let mut sess = ws.session.lock();
                                let mut atts = sess.attachments().to_vec();
                                if !atts.iter().any(|a| {
                                    matches!(a.kind, crate::session::PersistedAttachmentKind::Md)
                                }) {
                                    atts.push(crate::session::PersistedAttachment {
                                        alias: crate::connections::MD_ALIAS.to_string(),
                                        kind: crate::session::PersistedAttachmentKind::Md,
                                    });
                                    let _ = sess.set_attachments(atts);
                                }
                                drop(sess);
                            }
                            // Set the message AFTER status (set_md_status never
                            // touches md_test_result).
                            ws.connections.set_md_test_result(message.clone());
                            cx.notify();
                        });
                    }
                });
            } else {
                tracing::warn!("spawn_md_test: no MainThreadDispatcher installed; result dropped");
            }
        });
    }
```
