## Outcome summary

P4b lands the typed `Edit` + `RowDelete` transforms with a `RowKey` surrogate,
an SQL overlay render (`* REPLACE` + `WHERE NOT IN`) that filters/sorts wrap so
edits are visible downstream, keyboard-operable cell selection, a type-aware
inline cell editor, an RFC-style TSV clipboard (cut/copy/paste), fill-down +
bulk ops, a selection-aware context menu, the dirty-tab indicator, session v3,
and the PD-016 UI-click wirings P4a deferred.

Two significant gaps surfaced during execution and were closed as
user-approved scope additions (see PD-017, PD-018): file imports were lazy
DuckDB **views** (couldn't carry the surrogate), and the grid had never
rendered real cell values (P3a-era placeholder). Both are now closed, so the
feature is interactively demonstrable and ready for the manual UAT gate.

Full workspace gate green throughout: `cargo fmt --all -- --check`,
`cargo clippy --workspace --all-targets -- -D warnings`, `cargo test
--workspace` — 0 failures (86 test suites; baseline was 74, +12 P4b suites).

## Bench numbers (view_regen parity)

No new perf gate in P4b. The P4a `view_regen` baseline must stay green; P4b
guarantees this **structurally**, not just empirically: when a transform stack
contains no `Edit`/`RowDelete`, `compile_view_sql` runs the original P4a flat
assembly verbatim (top-branch) and emits byte-identical SQL — pinned by
`edit_render::no_edits_emits_flat_p4a_sql`. The overlay adds cost only to views
that actually carry edits/deletes. P4a baselines for reference: macOS-arm
229 ms p95 / linux-x86 295 ms upper-95% CI (500 ms gate). Re-running the heavy
`view_regen` bench on the branch PR (`run-heavy` label) is recommended at
merge time to confirm, but no regression is expected on the no-edit path.

## Lessons learned

1. **Adversarial review against real library behavior pays off.** The
   highest-value catch of the run — PD-017's transient-view leak — came from a
   quality reviewer checking duckdb-rs 1.4.4's actual transaction semantics
   (`execute_batch` is autocommit; even `BEGIN/COMMIT` doesn't auto-rollback a
   failed statement, so an explicit `ROLLBACK` is mandatory). The happy-path
   tests + spec review had both passed.
2. **Plan-snippet drift recurs and propagates.** The serde internally-tagged
   `RowKey::Surrogate(i64)` → `{ id: i64 }` change (T1) rippled into T2's render
   match and every golden. Catching it at T1 and broadcasting the struct form to
   downstream task briefs avoided N separate rediscoveries.
3. **"Lazy-init guard that only checks `None`" is a silent-bug pattern.** T6's
   selection survived a data-source swap with stale dimensions and failed
   *safely* (no-op guard) — invisible to tests. Reset cache-like fields at the
   swap point.
4. **The grid never rendered real data (PD-018).** Engine + view-state + filter
   + sort all shipped (P3a/P3b/P4a) on a placeholder grid delegate; P4b built
   the edit/clipboard logic on top, all test-green, but the feature wasn't
   demonstrable until the paged-render cache was wired. Worth wiring the visible
   surface earlier in a UI-feature stack.
5. **Per-task `cargo fmt`.** Per-task steps ran clippy but not rustfmt, so
   several commits weren't fmt-clean until a normalization pass. Add
   `cargo fmt --all` to the per-task pre-commit checklist (done for T6+).
6. **DCO sign-off didn't always stick** on subagent commits despite `-s`;
   verify `Signed-off-by` after each commit (normalized branch-wide before push).
7. **Launch the app at least once — tests don't run the GPUI event loop.** The
   single most important runtime bug (the tokio-runtime-not-entered crash that
   broke every file load) was invisible to 426 green tests and only surfaced on
   the first real `dat0 <file>` launch. A "does it boot + load a file + render
   without panicking" smoke launch belongs in the per-phase definition of done
   for any GUI-touching work, not just the manual UAT at the end.

## UAT — runtime smoke (automated, DONE) + the manual gate (user)

**Automated runtime smoke — PASS (and it found a ship-blocker).** Launching the
real binary `dat0 tests/fixtures/small/basic.csv` initially **panicked at
`file_drop.rs:76`**: `run_app` built a tokio runtime but never entered it for
the GPUI event loop, so `handle_drop`'s `spawn_blocking` (and every
`spawn_view_change`/prefetch `tokio::spawn`) ran on GPUI's main-thread executor
with no tokio context — the app crashed on **any** file load. Invisible to all
426 tests because none run the real event loop; latent until P4b made the
GUI→engine round-trips live (T0 clicks + PD-018 render/prefetch). Fixed by
holding `runtime.enter()` across `Application::run`. **Post-fix smoke confirms:**
the app launches, imports + materializes the CSV (`CLI paths processed on cold
start n_registered=1` — PD-017 path works at runtime), binds + renders the grid,
and stays alive with **no panic** — empirically confirming the `render_td`
weak-handle selection read (the PD-018 re-entrancy concern) is safe at runtime.

**Not automatable from the agent shell:** screen capture and System Events
keystrokes require macOS Screen-Recording / Accessibility permissions this
context lacks (`screencapture` → "could not create image from display"), and
driving Excel.app / Google Sheets is inherently cross-app. So the visual +
cross-app + keyboard parts remain the user's manual gate below.

## Manual UAT runbook (the headline exit gate — to be run by the user)

The app is now demonstrable and verified to launch/render/import without crash.
In a release build:

1. **TSV round-trip — Excel & Google Sheets (both directions):**
   - Import a CSV; select a discontiguous range whose cells contain tabs,
     newlines, double-quotes, and unicode → Cmd+C → paste into **Excel** and
     into **Google Sheets**; confirm cell-exact placement.
   - Copy a block **from** Excel and **from** Sheets back into dat0 → confirm
     cell-exact round-trip, with coerce-or-skip on type-incompatible cells and
     the paste-reject banner reporting the skipped count.
2. **Keyboard-only selection sweep:** arrows (move), Shift+arrows (extend),
   Cmd/Ctrl+arrows (jump-to-edge), Cmd/Ctrl+A (select-all), Escape (clear);
   Enter/F2 (edit), Cmd/Ctrl+C/X/V, Delete (set-null), Cmd/Ctrl+D (fill-down);
   confirm the focus ring tracks the active cell.
3. **Edit lifecycle:** edit a cell (dirty dot appears) → filter on the edited
   value (sees the edit) → undo (dot clears) → redo → delete rows → right-click
   context menu actions.
4. **Crash/restore:** apply edits + a delete, force-quit, relaunch → the active
   stack + cursor restore and the grid shows the overlaid values.

Record results here when run. **Do not consider the TSV + a11y exit criteria
fully met until both UAT directions pass.**
