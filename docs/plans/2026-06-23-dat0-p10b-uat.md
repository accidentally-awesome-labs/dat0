> **Phase:** P10b (a11y gate + real Settings window + privacy docs)
> **Tester:** perform on a local build (`cargo build`) or a signed release build.
> **Notation.** [ ] = not yet tested; [x] = PASS; [!] = FAIL (note details)

## Prerequisites

- Build from branch `p10b-hardening` (or post-merge `main` once P10b is merged).
- No prior Settings state needed; the tests cover both fresh state and persist/reload.
- For the Settings persist tests (§2): quit and re-launch between sub-steps so
  the store round-trip is verified through a full process restart.

## Known caveats (read before testing)

The following are v1 limitations to expect; they are **not** test failures:

1. **Telemetry "Learn more"** opens
   `https://github.com/accidentally-awesome-labs/dat0/blob/main/docs/privacy.md`
   — this URL returns 404 until the repo goes public (P11). The browser
   opening itself (no crash, link fires) is the PASS condition here.

2. **MotherDuck and AI sections show a static status line.** Live
   "connected / ready" state is v1.x (`md_status()` / `is_ai_ready()`
   accessors are not yet wired into the Settings panel). The static
   placeholder label is expected.

3. **MotherDuck "Manage connections…" and AI "Configure AI…" buttons require a
   workspace window to be open.** The buttons toggle a dock in the *focused
   workspace window* via `focused_workspace_weak()`. If only the Settings
   window is open, the click is a no-op (a `WARN` appears in the log; no
   crash). Open a workspace first, then open Settings to test these buttons.

4. **Memory Budget applies to NEW windows only.** Changing the MB value in
   Settings and pressing Enter persists the value; it takes effect the next
   time a workspace window is opened. No live re-apply on a running
   connection. This is the documented v1 behavior (closes D-014; live
   re-apply = v1.x note).

5. **Crash submission (Telemetry toggle)** persists the preference but the
   submission backend is not yet configured (P10c). The toggle correctly
   gates `Telemetry::init`; no reports are actually sent until P10c.

## 1. Settings window opens (real mount)

> Verifies that View → Settings… opens the REAL `SettingsPanel` window (not
> the old stub that only logged "stub — T13 wires the real window").

- [ ] **1.1** Launch dat0 (any workspace or Home screen).
- [ ] **1.2** Open **View → Settings…** (or press **Cmd-,** on macOS / **Ctrl-,**
      on Linux). Confirm a dedicated Settings window appears — distinct from the
      main workspace shell — with a sidebar on the left and a content pane on the right.
- [ ] **1.3** Confirm the sidebar lists exactly **9 sections** in this order:
      Profile · Theme · Memory Budget · MotherDuck · AI · Telemetry ·
      Networked Workspaces · Updates · Advanced.
- [ ] **1.4** Confirm clicking each sidebar item renders a non-empty content
      pane (no blank pane, no "placeholder" text remaining).

## 2. Profile section — inputs persist across relaunch

- [ ] **2.1** Select the **Profile** section. Enter a name (e.g. `Test User`)

- [ ] **2.2** Close the Settings window (window close button or Cmd-W / Alt-F4).
- [ ] **2.3** Quit dat0 entirely, then relaunch.
- [ ] **2.4** Open **View → Settings…** → **Profile**. Confirm the name and email

## 3. Theme section — live switch across all three themes

- [ ] **3.1** Select the **Theme** section. Confirm the current theme label is
      shown on the cycle button (e.g. `Theme: dark`).
- [ ] **3.2** Click the theme cycle button once. Confirm:
      - The label updates to the next theme in the cycle
        (`dark → light → high-contrast → dark`).
      - The app's color scheme changes **immediately** (no relaunch required).
- [ ] **3.3** Repeat the click twice more to cycle through all three themes and
      return to the original. Confirm each step renders a visually distinct palette.
- [ ] **3.4** Close Settings and relaunch. Open Settings → Theme. Confirm the
      last chosen theme is restored.
- [ ] **3.5** (Eyeball contrast) In each of the three themes, confirm that:
      - Body text is clearly legible against the background.
      - Error / warning / success labels are distinguishable.
      - The selection highlight (selected row / cell) keeps text readable.
        Note: contrast gate ratios are in `docs/a11y.md` §2.

## 4. Memory Budget section — input persists; applies to new window

- [ ] **4.2** Clear the field and enter a new value (e.g. `2048`). The footnote
      "applies to new windows" should be visible below the input.
- [ ] **4.3** Close Settings. Quit dat0 and relaunch.
- [ ] **4.4** Open **View → Settings…** → **Memory Budget**. Confirm the field

- [ ] **4.5** Open a **new** workspace window (File → New Workspace or equivalent).
      Confirm the new window opens without crash. (The budget is applied at
      `Session::new` time; no in-session re-apply is expected — see caveat 4.)
- [ ] **4.6** Reset to `1024` for subsequent tests.

## 9. Advanced section

### 9.1 Diagnostics buttons

- [ ] **9.1.1** Open Settings → **Advanced**. Confirm the build version string
      and git SHA are displayed (e.g. `dat0 0.1.0 (abc1234)`).
- [ ] **9.1.2** Click **"Open log folder"** (or "Open logs"). Confirm the OS
      file manager opens the dat0 log directory (macOS: `~/Library/Caches/dat0/`
      or platform equivalent; Linux: `~/.cache/dat0/` or `$XDG_CACHE_HOME/dat0/`).
      Confirm the directory exists (logs are written on every launch).
- [ ] **9.1.3** Click **"Reveal config directory"**. Confirm the OS file manager
      opens the dat0 config directory (macOS: `~/Library/Application Support/dat0/`;
      Linux: `~/.config/dat0/` or `$XDG_CONFIG_HOME/dat0/`). Confirm
      `settings.toml` is present.

### 9.2 Log-level cycle

- [ ] **9.2.1** Confirm the log-level button shows the current level
      (default: `info,dat0=debug`).
- [ ] **9.2.2** Click it once. Confirm the label changes to `debug`.
- [ ] **9.2.3** Click again: → `error`. Again: → `warn`. Again: → `info,dat0=debug`
      (wraps). The cycle order is `error → warn → info,dat0=debug → debug → error`.
- [ ] **9.2.4** Set the level to `debug`. Close Settings. Quit and relaunch.
      Confirm the log-level button in Advanced still shows `debug`.
- [ ] **9.2.5** Restore to `info,dat0=debug` for normal operation.

### 9.3 Reset to defaults — confirm dialog

- [ ] **9.3.1** Pre-condition: change at least one setting away from its default
      (e.g. set Profile name to a non-empty value, set Memory Budget to 512).
- [ ] **9.3.2** Click **"Reset to defaults"** (ghost / secondary button). Confirm
      a **modal confirm dialog** appears with a title (e.g. "Reset settings to
      defaults?") and both **OK** and **Cancel** buttons.
- [ ] **9.3.3** Click **Cancel**. Confirm the dialog closes; the settings value
      set in step 9.3.1 is **unchanged**.
- [ ] **9.3.4** Click **"Reset to defaults"** again. This time click **OK**.
      Confirm the dialog closes. Quit dat0 and relaunch.
- [ ] **9.3.5** Open Settings. Confirm the settings reverted to their defaults
      (e.g. Memory Budget = 1024, Profile name = empty, Theme = dark, Telemetry
      toggle = OFF, log level = `info,dat0=debug`).

## 10. Keyboard-only reachability

> Tests that every interactive element can be reached and operated by keyboard
> alone, with a visible focus indicator at each stop. Corresponds to a11y
> checklist items A1 and A2 in `docs/a11y.md` §1.

- [ ] **10.1** Launch dat0. Using Tab / Shift-Tab only (no mouse), cycle through
      all focusable elements on the Home screen. Confirm each focused element
      has a **visible focus ring** (2 px ring or equivalent highlight).
- [ ] **10.2** Open **View → Settings…** via keyboard (Cmd-,). Confirm the
      Settings window receives focus.
- [ ] **10.3** Using Tab / arrow keys, cycle through the sidebar items. Confirm
      each sidebar item is reachable and pressing Enter / Space selects it.
- [ ] **10.4** In the Profile section, Tab to the Name input and type into it.
      Tab to the Email input and type. Confirm both inputs respond to keyboard.
- [ ] **10.5** In the Advanced section, Tab to **"Reset to defaults"** and press
      Space / Enter. Confirm the confirm dialog opens. Tab to Cancel and press
      Space / Enter. Confirm dialog closes.
- [ ] **10.6** In the main workspace shell (with a workspace open), confirm:
      - Data grid is reachable by Tab.
      - Arrow keys navigate grid cells.
      - Shift+Arrow extends the selection.
      - Cmd-A (macOS) / Ctrl-A (Linux) selects all rows.
      - Escape collapses the selection.
      - The SQL console input is reachable by Tab.
      - The Catalog tree is reachable and arrow-navigable.
- [ ] **10.7** In the AI panel (if the workspace has AI configured), confirm the
      prompt input is Tab-reachable and Enter submits.

## 11. Contrast eyeball (all 3 themes)

> The automated contrast gate passes in CI (`cargo test -p dat0-app --test
> theme_contrast_gate`). This step is a visual sanity check; measured ratios
> are in `docs/a11y.md` §2.

- [ ] **11.1** **Dark theme** (default): confirm body text, error/warning/success
      labels, and selected-row text are all clearly legible.
- [ ] **11.2** **Light theme**: switch via Settings → Theme. Confirm the same.
      Note: the tightest pair is `warning`/`background` at 4.87:1 — visually
      acceptable but not high-headroom; flag only if it appears borderline.
- [ ] **11.3** **High-contrast theme**: confirm extreme contrast is apparent
      (foreground/background = 21:1). Confirm no element becomes invisible or
      unreadable.
- [ ] **11.4** In each theme, confirm the **grid selection highlight**: a selected
      row or cell shows text that remains readable against the selection
      background. (a11y.md A2 — focus ring contrast UAT-pending; eyeball the
      2 px ring in each theme.)
- [ ] **11.5** Return to the preferred theme when done.
