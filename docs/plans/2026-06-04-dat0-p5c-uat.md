## Connections panel — open/toggle (T4–T5)
- [ ] **View menu** → "Connections" opens the Connections panel.
- [ ] Invoking "Connections" a second time (or the same keybind) **closes** the panel (toggle behavior).
- [ ] The panel shows a "MotherDuck" section and an "Attach SQLite…" button (see trim note below).

## MotherDuck connect — no stored token (T6–T7)
- [ ] Click **Connect** in the MotherDuck section with no previously stored token → a **token prompt** modal appears.
- [ ] Enter a valid MotherDuck token and confirm → panel shows **Connecting…** spinner.
- [ ] Panel transitions to **Connected**; the database-names list (from `duckdb_databases()`) appears under the MotherDuck section.

## Routing chip — query classification (T8–T10)
- [ ] Run a query referencing `md.*` only (e.g. `SELECT * FROM md.main.some_table LIMIT 5`) → timing chip reads `· md`.
- [ ] Run a local-only query (e.g. `SELECT 1`) → timing chip reads `· local`.
- [ ] Run a query that joins a `md.*` table with a locally registered table → timing chip reads `· mixed`.

## Boot auto-reconnect — keychain persistence (T11)
- [ ] **Quit and relaunch the app**, reopening the same workspace.
- [ ] The Connections panel shows **Connecting…** automatically on boot → transitions to **Connected** without re-entering the token.
- [ ] Open a **second workspace** that has never attached MotherDuck → confirm the panel shows Disconnected and NO network extension-load traffic occurs (non-md workspaces stay fully offline).

## Disconnect and forget token (T12)
- [ ] Click **Disconnect** → panel transitions to **Disconnected**; the database-names list clears.
- [ ] Click **Forget token** (or equivalent) → token removed from keychain.
- [ ] Click **Connect** again → token prompt appears (confirms keychain entry was purged).

## Error state — bad token (T13)
- [ ] Enter a deliberately **invalid token** and confirm → panel shows the **Error** state with an authentication error message.
- [ ] A **Retry** button is visible; clicking it re-enters the Connecting… → Error cycle (or prompts again if token prompt is required).

## Known non-blocking follow-ups (from whole-feature review)
1. **Attach SQLite UI deferred.** The panel "Attach SQLite…" button is a no-op stub (trim-valve ②). Engine `attach()`/`detach()` are fully implemented; only the "pick a file" UI entry point waits on a reusable native file-picker surface (no target phase assigned yet).
2. **Catalog enumeration is database-names-only.** `duckdb_databases()` returns the list of attached database names; per-table `TableOrigin::Attached` for tables inside attached databases is not yet tracked in the origin registry (see D-012 P5c note).
3. **AccessKit / screen-reader coverage.** The Connections panel + token-prompt modal are new surfaces requiring P10 AccessKit coverage (see D-015 P5c note).
4. **md integration test is `#[ignore]`.** `tests/md_attach.rs` is excluded from workspace test runs; it runs only in the CI `md-integration` job when `MOTHERDUCK_TOKEN` is present. UAT above is the manual stand-in.
