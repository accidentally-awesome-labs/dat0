## Outcome summary

P4a ships the full view-state infrastructure for dat0: a typed `Transformation` enum with tagged serde wire format, a SQL render layer (`compile_view_sql`) for Filter + Sort, a `create_or_replace_view` / `drop_view` engine surface backed by DuckDB temp VIEWs, a `ViewModel` with apply / undo / redo / clear / replace_at_cursor / set_sort and a 50-entry capped history, compact-inline filter popover (full op surface + IN-list distinct-values panel + regex validity), multi-column sort headers with shift-click + rank subscripts, session.json v2 schema migration with fsync-parent-dir durability fix, and Cmd/Ctrl+Z / Cmd/Ctrl+Shift+Z keybind dispatch wired through the P3b `ActionRegistry`.

The T0 spike confirmed Plan A (temp VIEW per chain change) at 229 ms p95 on macOS-arm — 2.2× headroom against the 500 ms gate. The linux-x86 number was not collected during the phase (no `run-heavy` trigger occurred before T15); it remains pending via the heavy.yml bench step added in T15. Four plan defects were discovered and logged (PD-013 through PD-016). One is unresolved at merge time: PD-016 (UI-click → ViewChange wirings) — Path B accepted, explicit hand-off to P4b T0 (see §"PD-016 decision" below).

## PD-016 decision — Path A / B / C

**Decision: Path B (defer to P4b T0).**

**Rationale:**

Path A would add 50–100 lines of `grid/mod.rs` + `filter_popover_entity.rs` click-handler glue to T15, expanding a doc-only task into a UI wiring task with its own review surface. T15 is T15, not T16.

More importantly, the missing wiring is not a blocker for the architectural deliverables P4a promised: the SQL render layer, the ViewModel with undo/redo, the session persistence, and the keybind dispatch path are all verifiably correct. T14's E2E suite (`view_restore_e2e.rs`) validates the entire apply → undo → redo → clear → crash → restore story via direct ViewModel API + real engine round-trips, which is the meaningful correctness signal for P4a's engine-layer work.

P4b T0 begins UI integration work (row-edit, clipboard, context menu, column ops) which requires the same click-handler infrastructure. Wiring funnel-click → popover-mount and sort-zone-click → `vm.set_sort` inside the same P4b T0 scope avoids two separate click-handler passes over `grid/mod.rs`. The hand-off is clean: `filter_popover_entity.rs` already emits `Outcome::Apply` / `Outcome::Clear`; `WorkspaceShell` already has `apply_view_change`; the missing piece is a caller of `spawn_view_change` in the click path, which P4b T0 can add in a focused wiring pass.

The alternative (Path C, inherit into P4b/c generically) was rejected in favor of naming P4b T0 explicitly so the hand-off is binding.

**P4b T0 must:**
1. Wire `grid/mod.rs` funnel-zone click → `filter_popover_entity.rs` mount + present via `WorkspaceShell`.
2. Wire `filter_popover_entity.rs` `Outcome::Apply` → `vm.apply` + `spawn_view_change` via focused-workspace lookup.
3. Wire `grid/mod.rs` sort-zone click (plain + shift) → `vm.set_sort` + `spawn_view_change`.
4. Add a click-path integration test (or extend an existing one) to verify the full UI-click → ViewChange → rebind loop.

## Lessons learned

1. **Tagged serde from the start.** PD-014 would not have been discovered if the design had used `#[serde(tag = "kind")]` from the beginning rather than `#[serde(untagged)]`. For any enum with nullable or same-primitive variants, untagged is a trap — the T1 author caught it via compile-time test failure, which is the right discovery moment, but authoring tagged forms in the design doc would have spared the rework.

2. **Plan cross-task wiring ownership must be explicit.** PD-016's root cause was four separate tasks (T7, T9, T10b, T12) each deferring click-handler glue to "T13", while T13 was never authored to include those wirings. Any task that defers a concrete integration step to a later task should name the specific plan section that will own it, not just the task number.

3. **Headless mount infeasibility is a planning input, not a late surprise.** The T0 probe correctly identified that `InputState::new` requires `&mut Window`, and the plan was updated (T10 → T10 + T10b split) before T10 began. The probe pattern (spend the spike day verifying preconditions, not just benchmarking) should be the default for any task that touches a new gpui-component widget.

4. **Bench collection timing.** The T0 plan note specified "trigger `run-heavy` before T1 merges." That didn't happen. Linux-x86 numbers should be treated as a hard pre-merge gate for perf-sensitive phases, not a post-T15 nice-to-have. Protocol for P4b+: add the `run-heavy` label on the branch PR at T0 completion, not at retro time.

5. **Session.json fsync fix was independent of the view-state work.** T8 fixed PD-002's session side as a by-product of adding the v2 schema. This is the right time (when you're already touching `session/store.rs`), but future phases should scan PD-002's still-open `settings/store.rs` side on entry — it's been open since P1.

## Manual UAT runbook

Steps to run manually before merging to confirm the full P4a UX story. Requires a macOS-arm dev build (`cargo build --release`).

1. **Drop a CSV.** Drag a CSV file (≥ 10 000 rows) onto the workspace shell. Confirm: table appears, first 100 rows render in the grid, column headers show funnel + sort zones.
2. **Apply a filter.** Click the funnel zone on a numeric column. *(Expected: filter popover opens — WILL NOT WORK until PD-016 is closed in P4b T0. Confirm the popover is reachable via the ActionRegistry as a workaround if present.)*
3. **Sort a column.** Click the sort zone on a text column. Confirm: column header shows ▲ rank subscript "1"; rows reorder.
4. **Shift-click a second column.** Shift-click the sort zone on a second column. Confirm: both headers show rank subscripts ("1", "2"); rows sort by both columns.
5. **Undo.** Press Cmd+Z. Confirm: second sort is removed (header loses rank subscript); rows revert to single-column sort.
6. **Redo.** Press Cmd+Shift+Z. Confirm: multi-sort is restored.
7. **Clear view.** Apply any filter/sort; then invoke "Clear view" (ActionRegistry). Confirm: all transforms removed; table shows original row order.
8. **Simulate crash.** Force-quit (`kill -9`) while a filter/sort is active. Confirm session.json exists in the scratch directory.
9. **Restart + restore.** Relaunch dat0. Confirm: the recovery banner appears; "Review" shows the orphaned session; "Open" reopens the tab with the active transform stack (filter + sort) restored and the view re-bound to the temp VIEW.
10. **Multi-tab.** Open two tabs. Apply different sorts to each. Confirm Cmd+Z in each tab undoes that tab's last operation independently; the other tab is unaffected.
