# dat0 P10a — Manual UAT checklist

Headless CI cannot verify Gatekeeper prompts, notarization stapling, DMG mount
behavior, AppImage double-click, or the update-nudge UI. This checklist captures
the manual passes a human must run on real machines. It **joins the standing
P4b / P4c / P5b / P5c / P6a / P8 / P9a / P9b UAT backlog** — none of that
earlier manual UAT has been run yet either.

Run this checklist against the **release artifacts** (downloaded from a GitHub
Release or from a `workflow_dispatch` dry run), not a local dev build. The point
is to verify the signed/notarized pipeline, not the app logic.

---

## Pre-requisites

- Access to the GitHub Release (or Actions run artifacts from a dry run).
- A macOS arm64 machine (or clean VM — see below) for the macOS section.
- A Linux x86_64 machine (or container) for the Linux section.
- The dat0 GPG signing public key imported into your local GPG keyring:
  ```bash
  gpg --import docs/dat0-signing-key.asc   # or however we distribute the key
  ```
- A sample `.dat0` file for the double-click test (export one from a running
  session, or use the included `demo.dat0` if available).

## Section 1 — macOS clean-VM install

Use a clean macOS VM so that the Gatekeeper experience matches a new user's.
If you have the tart runner set up per `docs/ci-mac-vm-runner.md`:

```bash
# Clone the gold image to a throwaway VM
tart clone dat0-runner-base dat0-uat-p10a
tart run dat0-uat-p10a
# Inside the VM, download dat0.dmg from the release page or copy from host.
```

A real macOS machine where dat0 has never been installed is equally valid.

### 1.1 Install from DMG — no "Open Anyway" prompt

- [ ] Mount `dat0.dmg` (double-click or `hdiutil attach dat0.dmg`).
- [ ] Drag `dat0.app` to Applications (or run from the mounted volume).
- [ ] Launch `dat0.app` from Finder.
- [ ] **Confirm: Gatekeeper shows NO "Open Anyway" dialog.** The app must open
      directly. (A "developer cannot be verified" sheet or a quarantine prompt
      means notarization or stapling failed.)
- [ ] The app opens to its normal initial state (scratch session or splash).

### 1.2 Double-click a `.dat0` file (S1 = PASS path)

The T0 spike confirmed `App::on_open_urls` is available in GPUI 0.2.2. Both
macOS and Linux double-click are in scope; this section covers macOS.

- [ ] In Finder, double-click the sample `.dat0` file.
- [ ] **Confirm: dat0 opens (or comes to the front if already running) and
      loads the package as a read-only Inspect window.**
- [ ] No "choose application" dialog — dat0 is registered as the handler for
      `.dat0` files via the `Info.plist` `CFBundleDocumentTypes` entry.

### 1.3 Help ▸ About box

- [ ] Open **Help ▸ About dat0** (or the equivalent menu item).
- [ ] The About dialog shows:
  - [ ] Version string matching the release tag (e.g. `1.0.0`).
  - [ ] Git SHA (short, 7+ hex chars) matching the tagged commit.
  - [ ] License identifier (`Apache-2.0`).
  - [ ] An acknowledgement of third-party licenses / link to NOTICE.

### 1.4 Update nudge

- [ ] In the About box (or via the update-check mechanism), confirm the update
      nudge is visible: a line indicating the current version and a
      **"Download latest"** (or equivalent) button/link.
- [ ] With a real newer GitHub Release available (version > current), confirm
      the nudge resolves — it detects a newer release and presents the
      download link.
- [ ] Click the Download / Releases link: **confirm it opens the browser to
      the GitHub Releases page** (`https://github.com/accidentally-awesome-labs/dat0/releases`).
- [ ] If no newer release exists, confirm the nudge shows "You are up to date"
      or similar (no crash, no error).

### 1.5 Artifact verification (macOS)

```bash
# In a terminal on the test machine:
shasum -a 256 dat0.dmg
# Compare the output to the SHA256SUMS file from the release.
```

- [ ] SHA-256 of `dat0.dmg` matches the entry in `SHA256SUMS`.
- [ ] `spctl --assess --verbose=4 dat0.app` (after mounting) reports
      `dat0.app: accepted` (source: Notarized Developer ID).

## Section 2 — Linux clean install

Use a clean Ubuntu 24.04 container or VM (the same baseline the CI uses):

```bash
docker run --rm -it -v /path/to/artifacts:/art ubuntu:24.04 bash
```

Or a real Linux x86_64 machine where dat0 has never been installed.

### 2.1 Run the AppImage — no permission errors

- [ ] Make the AppImage executable: `chmod +x dat0.AppImage`
- [ ] Run it: `./dat0.AppImage`
- [ ] **Confirm: it launches without FUSE errors or permission denials.** (The
      AppImage must be self-contained; `libfuse2` must be available or the
      AppImage must fall back to extraction mode.)
- [ ] The app opens to its normal initial state.

### 2.2 Install `.desktop` entry and MIME association

- [ ] Run: `./dat0.AppImage --appimage-install` (or the xtask install command).
- [ ] Confirm `~/.local/share/applications/dat0.desktop` exists (or
      system-wide equivalent).
- [ ] Confirm `~/.local/share/mime/packages/dat0.xml` exists and
      `update-mime-database` has run (or equivalent).

### 2.3 Double-click a `.dat0` file (Linux)

- [ ] In a file manager (Nautilus / Thunar / etc.), double-click the sample
      `.dat0` file.
- [ ] **Confirm: dat0 opens and loads the package as a read-only Inspect
      window.** No "choose application" dialog — dat0 is registered as the
      handler.

### 2.4 Artifact verification (Linux)

```bash
# Verify SHA-256
sha256sum dat0.AppImage
sha256sum dat0.AppImage.sig
# Compare both to SHA256SUMS from the release.

# Verify GPG signature
gpg --verify dat0.AppImage.sig dat0.AppImage
# Must print: "Good signature from ..." with the dat0 signing key.
```

- [ ] SHA-256 of `dat0.AppImage` matches `SHA256SUMS`.
- [ ] SHA-256 of `dat0.AppImage.sig` matches `SHA256SUMS`.
- [ ] `gpg --verify` prints **"Good signature"** with no trust warnings (after
      importing the dat0 public key).

### 2.5 Second launch forwards into the running instance (both platforms)

Run this on **both** the macOS VM (Section 1) and the Linux VM. It lives here
rather than in an automated test because a true headless check would need
`Application::run` on the platform main thread plus an X11/Wayland/Cocoa
connection, neither of which `cargo test` can supply. It used to exist as
`crates/dat0-app/tests/single_instance.rs::second_launch_spawns_visual_window`,
an `#[ignore]`d function whose body was `unimplemented!()` — a test that ran
nowhere and asserted nothing, deleted in QA2. This checklist is where it
actually gets exercised.

The automated half is already covered:
`single_instance.rs::second_launch_forwards_and_dispatches_to_main_thread`
proves the UDS message is received and dispatched exactly once to the main
thread. What no test can prove is that the dispatch produces a **visible
window**. That is what this section is for.

- [ ] Launch the app from one shell and leave it running.
- [ ] From a **second** shell, launch it again with no arguments.
- [ ] The second invocation **exits** rather than opening its own process
      window.
- [ ] A second window appears in the **first** instance, in front and focused.
- [ ] Repeat with a file argument (`dat0 some.csv`): the file opens in a new
      window of the first instance, not a second process.
- [ ] Quit the first instance. Confirm the shutdown log reports the expected
      `WindowRegistry::len()` — that is the observable window count.
- [ ] Launch once more after the quit: it must start a **fresh** instance
      (the lock file was released, not orphaned).

> See `docs/internal/gpui-api-notes.md` §0.A.11 for the manual UAT path.

## Section 3 — `workflow_dispatch` dry run

Before cutting the first production release tag, run at least one
`workflow_dispatch` dry run to validate the pipeline without publishing.

```bash
gh workflow run release.yml
gh run list --workflow=release.yml --limit 3
gh run watch <run-id>
```

### 3.1 Dry-run checklist

- [ ] Both `macos` and `linux` jobs complete green.
- [ ] `publish` job is **skipped** (expected — it is gated on `ref_type == 'tag'`).
- [ ] Artifacts `dat0-dmg` and `dat0-appimage` are available in the Actions
      run summary and can be downloaded.

### 3.2 GPG passphrase wiring verification (CRITICAL)

> This is the **known dry-run blocker** documented in `docs/release-runbook.md`
> under "Linux GPG signing — passphrase wiring".

- [ ] Download `dat0.AppImage` and `dat0.AppImage.sig` from the dry-run
      artifacts.
- [ ] Run `gpg --verify dat0.AppImage.sig dat0.AppImage` locally.
- [ ] **Confirm: "Good signature"** is printed. If you see a `gpg: signing
      failed: No secret key` or passphrase error, the passphrase is not wired
      to the sign step. Resolve using option (a) or (b) from the release
      runbook before cutting a production tag.
- [ ] Record the resolution (passphraseless key or loopback wiring) in
      `docs/release-runbook.md` under the GPG note.

### 3.3 Record keeping

- [ ] Record the dry-run Actions run URL here (or in release notes):
      `https://github.com/accidentally-awesome-labs/dat0/actions/runs/<run-id>`
- [ ] Confirm the pipeline wall-clock time (expected: ~20–40 min for macOS
      build + notarization, ~10 min for Linux).
