# dat0 P10a — Release Pipeline (signing · notarization · packaging · update-nudge)

> **Design doc.** Brainstormed 2026-06-17. First slice of P10 ("Hardening + perf
> gates + signing", master spec §21.2 P10). Decomposes P10 and scopes P10a to the
> unblocked shippability spine: package + sign + notarize + verify-install on both
> platforms, plus a minimal in-app update *nudge*. Full auto-update is sequenced
> into a following slice (P10a-2). Next step after user review: `writing-plans`.

---

## 1. Why this slice exists

The master spec's P10 ("Hardening + perf gates + signing", §21.2, ~3 weeks) spans
seven largely-independent subsystems: perf-gate CI, packaging+signing, auto-update,
crash reporting, accessibility, docs/runbooks, and a beta channel. That is too
broad for one spec — consistent with P3/P4/P5/P7/P9 all having been split.

The split is shaped by what external infrastructure actually exists. Confirmed
2026-06-17:

- **Available:** Apple Developer Program enrollment + Developer ID cert +
  notarization (App Store Connect) API key.
- **Not available:** dedicated Mac hardware for a GPU-class perf-gate runner
  (D-013); a GlitchTip instance; a beta-tester cohort.

That cleanly partitions P10:

| Slice | Scope | Status |
|---|---|---|
| **P10a** *(this doc)* | Universal signed/notarized macOS DMG + signed Linux AppImage + About box + `.dat0` association + minimal update-nudge + runbooks + NOTICE-refresh gate | **now — unblocked** |
| **P10a-2** (updater) | Full in-app auto-update. T0 spike decides mechanism: Sparkle↔GPUI run-loop probe → pass = Sparkle (objc2 bridge, reuse EdDSA scaffolding); painful = `cargo-packager` unified updater. Closes D-003 / D-004. | next |
| **P10b** | a11y audit checklist + `docs/a11y.md` + AccessKit re-check (D-015) + Settings §24.2 all-sections completeness gate + privacy-review doc | later |
| **P10c** | GPU perf-gate runner (D-013) · GlitchTip crash-submit flip + e2e · beta channel | deferred until HW / instance / testers exist (advisory benches already run in CI) |

**Why auto-update is sequenced out of P10a.** The single biggest unknown in the
whole update story is whether Sparkle's `SPUStandardUpdaterController` can drive
GPUI's *custom* run loop — GPUI owns its own `NSApplication` + event loop and is
not a standard AppKit app. That is a spike question, not a commit-blind decision.
Moreover, packaging + signing + notarization is a hard prerequisite to testing
*any* updater (Sparkle or cargo-packager) — you cannot validate update delivery
without signed/notarized artifacts and a host serving them. So P10a nails the
signing pipeline + a cheap "new version available → open Releases" nudge; the
risky 30% (the real updater) follows in P10a-2 where a spike picks the mechanism.
Nothing is wasted: the pipeline must exist first either way.

## 2. Scope / non-goals

**In scope (P10a):**

- macOS: **universal** (`aarch64` + `x86_64`, `lipo`'d) `.app` → Developer ID
  sign → notarize → staple → signed `.dmg`.
- Linux: `.AppImage` → GPG detached signature; `.desktop` + shared-mime-info for
  `.dat0` association.
- App icon: generated programmatic **`d0` placeholder wordmark** → real
  `.icns` + `.png` (swap for final art in v1.x / P11 launch polish).
- About box: version + build-hash + license + NOTICE acknowledgements + update line.
- Minimal update **nudge** (not auto-update): GitHub Releases latest → semver
  compare → "vX available → Download" opens Releases in browser.
- `release.yml` CI workflow (tag-triggered) producing + attaching signed artifacts.
- NOTICE refresh against final dep tree; existing `notice.yml` gate stays active.
- `docs/release-runbook.md` + `docs/security-runbook.md` (scoped to P10a's secrets).
- Clean-install verification: CLI gate (automatable) + clean-VM UAT (tart, reuses
  the existing `docs/ci-mac-vm-runner.md` infra from PR #6).

**Non-goals (explicit — each lands in a later slice):**

- In-app **auto-update** (download + swap + restart). Nudge only. → P10a-2.
- GPU-class perf-budget CI gates / self-hosted GPU runner. → P10c (D-013).
- GlitchTip crash-submission flip + e2e verify. → P10c.
- Beta channel / tester cohort. → P10c.
- a11y audit checklist, AccessKit, Settings §24.2 completeness gate. → P10b.
- Final brand art, DMG marketing background polish. → v1.x / P11.

## 4. As-built starting point (verified 2026-06-17)

- **Packaging is greenfield.** No bundle config, no Info.plist, no `.dmg`/AppImage,
  no `.desktop`, no icon. `ci.yml` does a bare `cargo build --release`.
- **Updater scaffolding exists (P1).** `crates/dat0-app/src/updater/`: `Updater`
  trait; `SparkleUpdater` does a live appcast smoke-GET, embeds an EdDSA pubkey via
  `include_str!(assets/sparkle-public-key.txt)`, reads `DAT0_SPARKLE_APPCAST_URL`;
  `AppImageUpdater` is a pure stub. The real SUUpdater Obj-C bridge (D-003) +
  `appimageupdatetool` subprocess (D-004) were always punted to P10 → now P10a-2.
- **File-open entry exists.** `main.rs` reads `std::env::args().skip(1)` into
  `cli_paths` → Linux `.desktop %F`→argv lands here. macOS double-click arrives via
  AppKit `application:openURLs:` (not argv) → see spike S1.
- **CI matrix:** hosted `macos-14` (arm64) + `ubuntu-latest` (x86_64). Signing /
  notarization run fine on hosted macOS (cert in secrets) — the missing dedicated
  HW was only ever for the P10c GPU perf-gate runner, not for signing.
- **tart mac-VM runbook present** (`docs/ci-mac-vm-runner.md`, PR #6) with
  snapshot/clone primitives — reused for D4 clean-install UAT.

## 5. Architecture & components

Each unit has one purpose, a defined interface, and is independently testable.

### 5.1 `xtask` crate (build/release mechanics)

- `xtask::gen_icon` — programmatic `d0` wordmark → macOS `.iconset`→`.icns` and the
  Linux `.png` size set. Pure + deterministic. *Test:* output files have valid
  `.icns`/PNG magic + expected sizes.
- `xtask::bundle_macos` — build `aarch64-apple-darwin` + `x86_64-apple-darwin`;
  `lipo -create` → fat binary; assemble `dat0.app/Contents/{MacOS,Resources}`;
  write `Info.plist` (version, build-hash, `CFBundleDocumentTypes` + `UTImportedTypeDeclarations`
  for `.dat0`, icon ref). *Test:* bundle layout + plist keys present.
- `xtask::sign_macos` — `codesign --force --deep --options runtime --sign "Developer ID Application"`
  → `notarytool submit --wait` (App Store Connect API key) → `stapler staple`
  → `create-dmg` → sign the DMG. *Test:* dry-run path assertions; real signing only
  in CI with secrets.
- `xtask::bundle_linux` — `linuxdeploy` + `appimagetool` → `dat0.AppImage`; emit
  `dat0.desktop` (`MimeType=application/x-dat0;`, `Exec=dat0 %F`) + shared-mime-info
  XML registering `.dat0`; GPG detached `.AppImage.sig`. *Test:* AppImage exists +
  runs `--version` under Docker Ubuntu.

### 5.2 App-side surfaces

- `update::UpdateCheck` (generalized from `SparkleUpdater`) — GET GitHub Releases
  "latest" → parse tag → semver-compare vs `CARGO_PKG_VERSION` → `Option<NewVersion>`.
  Sparkle-agnostic; HTTP mockable. *Test:* pure semver-compare table; mocked-HTTP
  newer/older/equal cases.
- `BuildInfo` (`build.rs`) — embed git short-sha + build timestamp at compile time.
- `about` view — renders `BuildInfo` + license + NOTICE acknowledgements + the
  update line ("vX.Y.Z available → Download" → opens Releases URL via the OS opener).
  *Test:* renders from a fixture `BuildInfo`; update line present iff `UpdateCheck`
  returns `Some`.

### 5.3 CI — `release.yml` (git-tag `v*` triggered, separate from `ci.yml`)

1. **macOS leg** (`macos-14`): import Developer ID cert into a temp keychain →
   `xtask bundle_macos` → `xtask sign_macos` (notarize+staple) → produce signed DMG.
   Secrets: `APPLE_DEV_ID_CERT_P12`(b64) + `CERT_PASSWORD`,
   `AC_API_KEY_P8` + `AC_KEY_ID` + `AC_ISSUER_ID`, `KEYCHAIN_PASSWORD`.
2. **Linux leg** (`ubuntu-latest`): `xtask bundle_linux` → GPG-sign.
   Secret: `GPG_PRIVATE_KEY` + `GPG_PASSPHRASE`.
3. **CLI verification gate** (§7): runs against the freshly-built artifacts; fails
   the job on any Gatekeeper/notarization/codesign assertion.
4. **Publish:** attach signed DMG + AppImage + `.sig` + SHA-256 checksums to the
   GitHub Release.
5. NOTICE: refresh against the final dep tree as part of the slice; `notice.yml`
   gate stays active going forward.

## 6. T0 spikes (gate the plan — run before dependent tasks)

- **S1 — macOS `.dat0` double-click.** GPUI delivers opened files via AppKit
  `application:openURLs:`, not argv. Probe whether the pinned GPUI surfaces this
  (open-file event / `cx` hook). **Pass:** wire it to the same `cli_paths`/open path.
  **Fail:** a thin Apple-event shim, or defer macOS-double-click to a deferral
  (Linux double-click still ships, which is the spec's hard Linux exit gate).
- **S2 — universal `lipo` + hardened-runtime notarization.** Confirm a framework-free
  GPUI binary statically linking Metal + DuckDB notarizes clean under
  `--options runtime` without extra entitlements, and that the `lipo`'d fat binary
  passes `notarytool`. **Fail:** enumerate required entitlements / per-arch signing.

## 7. Verification & exit criteria

**CLI gate (automatable, in `release.yml`):**
- macOS: write `com.apple.quarantine` xattr on the DMG → `spctl --assess -vvv`
  passes · `stapler validate` · `codesign --verify --deep --strict`.
- Linux: AppImage runs `--version` under a clean Docker Ubuntu LTS image; GPG
  signature verifies.

**Clean-VM UAT (manual, reuses PR #6 tart):**
- `tart clone` the gold image → genuinely clean macOS → download + install the
  notarized DMG → launch with no "Open Anyway" → double-click a `.dat0` (per S1).
- Clean Ubuntu VM/container → run the `.AppImage`, no permission errors → double-click
  a `.dat0` opens it.

**Exit criteria:**
- Signed DMG installs on clean macOS VM with Gatekeeper silent (no override).
- Signed AppImage runs on clean Ubuntu without permission errors.
- Double-clicking a `.dat0`: **Linux required**; macOS per S1 outcome.
- About box shows correct version + build-hash + license + NOTICE; update line
  resolves against a real newer GitHub Release.
- NOTICE refreshed; `notice.yml` gate green.
- `docs/release-runbook.md` + `docs/security-runbook.md` committed.
- Manual clean-VM UAT checklist run + logged (joins / clears its part of the
  standing UAT backlog).

## 8. Deferral-register impact (apply during plan execution)

- **D-003 (Sparkle bridge)** / **D-004 (AppImageUpdate)** — stay **open**; retarget
  P10 → **P10a-2** (the updater slice). P10a ships the nudge, not the bridge.
- **D-006 (Intel CI coverage)** — *advanced*: universal build adds the `x86_64`
  build leg. Full Intel *test* matrix remains optional/open.
- **D-013 (self-hosted macOS GPU runner)** — unchanged; P10c.
- **D-015 (AccessKit)** — unchanged; P10b.
- **New deferral (conditional):** macOS `.dat0` double-click, opened only if spike
  S1 forces deferral.
- **New note:** EdDSA appcast-signing key rotation — `security-runbook` records it
  as pending P10a-2 (the shipped P10a code does not yet consume the key).

## 9. Out of scope for this design

contents, and final brand art are explicitly deferred to their own brainstorms.
