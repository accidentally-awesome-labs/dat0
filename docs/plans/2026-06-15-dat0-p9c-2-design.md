## 1. Framing

P9c-2 builds the **user-facing AI features** on P9c-1's secure foundation.
Everything outbound still flows through the schema-only `AiRequest` + SSRF +
`transport`; this slice adds the *callers* (which assemble real schema context +
prompts), a **streaming** transport path, and the **per-context inline UI**. No new
network security surface — the only new outbound shape is SSE over reqwest's
already-enabled `stream` feature.

**App-only slice** (mirrors P9c-1 / P9b): **no `dat0-engine` lib change, no
`session.json` schema bump.** AI config stays in global `settings.toml` + keychain;
the whole-workspace schema is read from the shell's already-cached
`catalog_tables`.

## 2. Locked decisions

- **D1 — One slice, all three features.** Streaming primitive + NL→SQL chip +
  Explain ship together; they share the SSE primitive so the marginal cost of the
  2nd/3rd feature is small. *(User pick over a streaming-first / Explain-second
  split.)*

- **D2 — Per-context inline output (no unified AI view).** NL→SQL streams into a
  **preview strip** inside the SQL Console (between editor and results); Explain
  streams into its **own side panel** by the editor. The P9c-1 AI dock stays
  **config-only**. *(User pick over extending the AI dock into a chat surface or
  building a new dedicated AI-Assistant dock.)*

- **D3 — NL→SQL never auto-runs (hard req).** The chip emits SQL into a preview
  strip; **Insert** opens it in a **new pre-filled console tab** (`load_into_new_tab`,
  the proven history/saved-query path) — never clobbers the active buffer, never
  executes. *(Insert behaviour = new-tab, user pick over replace-buffer /
  insert-at-cursor; insert-at-cursor needs an editor API that may not exist at the
  pinned gpui-component.)*

- **D4 — Explain target = whole active-tab buffer.** Text selection is unavailable
  at the pinned gpui-component (the same limit that made P5a Run cursor-only), so
  Explain takes the entire tab SQL as one block. *(User pick over cursor-statement.)*

- **D5 — Schema scope = whole workspace, capped.** NL→SQL/Explain send **all**
  catalog tables' names+types, truncated to a cap (`max_tables` / `max_cols_per_table`)
  with a "… N more omitted" note so the model knows context is partial. Best NL→SQL
  quality (cross-table joins) within a bounded payload. *(User pick over
  active-table-only / user-selectable picker.)*

- **D6 — Single configured model.** Both features use the one `AiSettings.model`
  already in the panel. No new settings, no new UI. *(User pick over per-feature
  models.)*

- **D7 — Streaming via the existing thin seam (not an `AiSession` object).** Add
  `Wire`-level SSE parsing + `transport::send_stream`; the app consumes it as a
  loop-variant of `spawn_ai_test` (weak-handle upgrade after await, `cx.notify` per
  delta, `ai_stream_load_id` supersede). *(Recommended approach; rejected a
  higher-level session/lifecycle object as manufactured complexity for two one-shot
  features.)*

- **D8 — One shared stream at a time.** A single `ai_stream_load_id` supersede
  counter spans both features: a new NL→SQL or Explain request cancels any in-flight
  stream of either kind. Keeps the model simple; no concurrent-stream coordination.

- **D9 — Errors/refusals render inline-red** in the originating surface (preview
  strip / Explain panel), mirroring P9c-1's `test_result_message`. No banner spam.
  Partial SQL is never auto-run regardless of how a stream ends.

## 3. Module layout — extend `crates/dat0-app/src/ai/`

| File | Change | Purity |
|---|---|---|
| `wire.rs` | add `parse_sse_delta(&str) -> Option<String>` per wire (Anthropic `content_block_delta` vs OpenAI-compat `chat.completion.chunk`); `build_body` gains a `stream: true` variant | **pure** |
| `transport.rs` | new `send_stream(provider, key, cfg, req, on_delta)` — SSRF-gated (reuses `resolve_base_url`), reqwest `bytes_stream()`, SSE line-buffer → `on_delta(&str)`; returns the final full text | network seam |
| `schema_ctx.rs` *(new)* | pure `build_schema_context(&[TableInfo], SchemaCaps) -> (SchemaContext, Option<String>)` — first real population of `AiRequest.schema` | **pure** |
| `prompt.rs` *(new)* | pure fixed system prompts: `nl_to_sql_system()` / `explain_system()` | **pure** |
| `view/sql_console.rs` | NL→SQL chip + preview-strip state/render; Explain button + side-panel state/render | GPUI shell |
| `window.rs` | `spawn_ai_nl2sql` / `spawn_ai_explain` (loop-variant of `spawn_ai_test`) | GPUI shell |

Pure kernel (`wire`/`schema_ctx`/`prompt`) stays offline-unit-testable; `transport`
remains the only network code; SQL console + window are the thin GPUI shell — same
shape as P9c-1, `charts/`, `inspector/`, `connections/`.

## 4. Streaming primitive (D7)

`transport::send_stream`:

```
async fn send_stream(
    provider: Provider, key: &str, cfg: &AiSettings, req: &AiRequest,
    mut on_delta: impl FnMut(&str),
) -> Result<String>   // returns the full accumulated text
```

- Reuses `resolve_base_url` (SSRF + DNS-rebind recheck for Custom) verbatim.
- `build_body(..)` with `stream: true`; POST; consume `resp.bytes_stream()`.
- SSE line-buffer: accumulate bytes, split on `\n`, strip `data: ` prefix, ignore
  `[DONE]` / empty keep-alives, hand each JSON line to `wire.parse_sse_delta(line)`
  → `Some(text)` → `on_delta(text)` + append to the accumulator.
- Non-2xx → surface the raw body (lossy) exactly like `send`.
- Bounded read; a Stop on the app side drops the future (supersede) — no server
  cancellation needed.

`Wire::parse_sse_delta`:
- **Anthropic Messages SSE:** `content_block_delta` events → `delta.text`.
- **OpenAI-compat SSE:** `chat.completion.chunk` → `choices[0].delta.content`.
- Resolve exact event shapes at **build time** — Anthropic via the `claude-api`
  skill, OpenAI/OpenRouter via context7 — not from memory.

App consumption (`spawn_ai_nl2sql` / `spawn_ai_explain`): `tokio::spawn` the
`send_stream` (Send engine work), each delta hops to the main thread via
`window_registry::dispatcher()` and `ws.update(..)` to mutate the console state +
`cx.notify`. Mirrors the P9a-1 off-thread→dispatcher→main pattern, but the payload
is **text** so there is no `!Send`/`RenderImage` concern — confirm only the
`bytes_stream` + per-delta-notify shape in the T0 spike.

## 5. NL→SQL chip + preview strip (D2/D3)

**Chip** in the SQL Console toolbar (beside Run/Explain). Disabled unless
`enabled && key_set && !model.is_empty()` (P9c-1 gate); disabled tooltip says why.
Click → an inline single-line prompt input (confirm the gpui-component input idiom
at build time; the name-prompt pattern is the fallback).

**Preview strip** — collapsible region below the editor, above the results pane.
New `SqlConsole` state:

```
nl_preview: Option<NlPreview>          // None = strip hidden
struct NlPreview { prompt: String, sql: String, streaming: bool, error: Option<String> }
```

Flow:
1. Submit → strip opens, `streaming: true`, **Stop** shown.
2. Each delta appends to `sql`, `cx.notify` repaints (plain monospace text; the real
   editor highlights only after Insert).
3. Finish → `streaming: false`; **Insert** + **Discard** appear.
4. **Insert** → `load_into_new_tab(sql)` → strip clears. **Never runs.**
5. **Stop** → flip `ai_stream_load_id` (drop the in-flight stream); partial text kept
   with Insert/Discard still available.
6. New prompt mid-stream → supersede cancels the old, restarts.

---

## 6. Explain side panel (D4)

**Explain button** in the toolbar beside Run (same gate as the chip). Target =
whole active-tab buffer. New `SqlConsole` state mirrors the strip:

```
explain: Option<ExplainView>           // None = panel hidden
struct ExplainView { sql: String, prose: String, streaming: bool, error: Option<String> }
```

Flow:
1. Click → grab whole buffer → `AiRequest { system: explain_system(), schema: capped_ctx, prompt: <buffer SQL> }` → side panel opens, streaming.
2. Deltas append to `prose`, `cx.notify` per chunk (rendered as plain text — no
   markdown engine; deferred).
3. Finish → Stop replaced by **Close (✕)**.
4. Stop / re-Explain → same `ai_stream_load_id` supersede (D8: shared with NL→SQL).

Panel placement = right of (or below) the editor, matching the console's existing
dock idiom; confirm exact layout at build time. Schema context is included for
Explain too (helps the model name columns), still names+types only.

## 7. Schema-context assembly (D5) + R17

New pure `ai/schema_ctx.rs`:

```
struct SchemaCaps { max_tables: usize, max_cols_per_table: usize }
fn build_schema_context(tables: &[TableInfo], caps: SchemaCaps) -> (SchemaContext, Option<String>)
```

- Source = the shell's already-cached `catalog_tables: Vec<TableInfo>` (refreshed by
  `refresh_catalog`) — no engine call on the prompt hot path.
- Maps `TableInfo` → `TableSchema { name, columns: [{name, ty}] }`. Names + types
  only; `TableInfo`/`ColumnInfo` carry no values, so this is **schema-only by
  construction** (R17 holds the same way P9c-1's type discipline does).
- Caps (defaults `max_tables: 40`, `max_cols_per_table: 60` — tune at build time):
  truncate beyond the cap; return a note (`"… 12 more tables omitted"`) appended to
  the schema block so the model knows context is partial.
- The internal surrogate `__dat0_rowid` is filtered out (known internal-column
  pattern from the Inspector work).
- `include_sample_rows` unchanged: NL→SQL/Explain do **not** populate `sample_rows`;
  the existing P9c-1 caller-gated toggle stays the only door to row data.

**R17 regression lock:** extend the P9c-1 payload-filter fixture — feed a
`build_schema_context` result through `build_body` for **both** wires, assert no row
values leak, and assert the cap note appears when tables exceed the cap. The existing
`SECRET_ROW_VALUE` guard stays green.

## 8. Gating, errors, privacy (D9)

- **Gating** (P9c-1): chip + Explain disabled unless `enabled && key_set &&
  !model.is_empty()`. No key ⇒ no `send_stream` call ⇒ no outbound (structural).
- **Errors/refusals** inline-red in the originating surface: HTTP error body (lossy,
  like `send`), Anthropic `stop_reason: "refusal"`, rate-limit 429. Never auto-run
  partial SQL.
- **Privacy banner** already ships (P9c-1, show-once via `privacy_ack`). The copy
  ("schema names + prompt leave the machine; no row data unless include-sample-rows
  is on") already covers these features — no new banner.

## 9. T0 spike (gates the slice)

Minimal SSE→panel loop: `send_stream` against the live CI provider, deltas →
`cx.notify` into a throwaway strip. Confirms the off-thread→dispatcher→main repaint

(incl. partial lines spanning chunk boundaries + `[DONE]`). Resolve Anthropic SSE via
`claude-api`, OpenAI/OpenRouter SSE via context7 — at spike time, not from memory.

## 10. Testing / CI

- **Pure unit:** `parse_sse_delta` both wires (fixture SSE chunks incl. partial lines
  + `[DONE]` + keep-alives); `build_schema_context` (cap + truncation note + surrogate
  filter); `prompt` strings stable; **extended R17 payload fixture** (§7).
- **Live integration (env-gated, reuse P9c-1's `OPENROUTER_API_KEY` +
  `deepseek/deepseek-v4-flash`):** `send_stream` collects ≥1 delta and a non-empty
  final completion. Required-green in CI, lenient-skip locally (P9b-T6 pattern).
- **Anthropic SSE path:** unit-tested here; proven live in **manual UAT** (owed,
  joins the standing P4b/P4c/P5b/P5c/P6a/P8/P9a/P9b/P9c-1 backlog).
- **Full gate:** `cargo test --workspace`, clippy `--workspace --all-targets
  -D warnings`, fmt, i18n — grep `ai.*` keys **incl. format-constructed**
  (`format!("ai.…")` / `format!("menu.…")`, the P9c-1 whole-feature lesson). Bump the
  action-registry count **only if** a new action id is added — chip/Explain may be
  plain toolbar buttons (no action id); confirm at build time. NOTICE.md regen only if
  a new crate enters the tree (none expected — reqwest `stream` already enabled).

## 11. Security exit criteria (R17 — must not be deferred)

1. New schema-assembly carries **no** row data / query results / file paths — both
   wires, test-fixtured (§7); `include_sample_rows` stays the only row-data door.
2. Streaming path is the **same** SSRF-gated `resolve_base_url` as `send` — Custom URL
   still rejects http/loopback/RFC-1918/link-local/IPv6-ULA without the override; the
   DNS-rebind resolved-IP recheck still runs (§4).
3. AI fully off without a key ⇒ chip/Explain disabled ⇒ no streaming call (§8).
4. Key never in logs / `settings.toml` / telemetry (P9c-1 guards unchanged).

## 12. Deferrals opened

- Multi-turn chat / conversation history (P9c-2 is one-shot per prompt).
- Markdown rendering of Explain prose (rendered as plain text now).
- Per-feature models (single configured model now, D6).
- Insert-at-cursor (new-tab now, D3).
- DNS-rebind **connection-pinning** — still carried from P9c-1 (resolved-IP recheck
  ships; full pinning is the standing hardening follow-up).

---

## 13. Risks / unknowns

- **GPUI streaming UX** — front-loaded into the T0 spike (§9).
- **Provider SSE drift** — Anthropic vs OpenAI-compat chunk shapes differ; resolve
  both at build time (`claude-api` + context7), never memorize.
- **OpenRouter model drift** — re-verify `deepseek/deepseek-v4-flash` is live at
  execution; swap to the cheapest current small paid model if retired (P9c-1 risk).
- **Prompt injection via schema names** — low (names are the user's own data), but
  keep system prompts firmly scoped to "emit SQL" / "explain"; **never execute
  returned SQL** (D3 enforces this structurally — Insert → new tab, manual Run only).
- **Editor insert API** — `load_into_new_tab` is proven; insert-at-cursor deferred
  precisely because the public API may not exist at the pinned gpui-component.
