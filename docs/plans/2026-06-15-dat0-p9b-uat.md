# dat0 P9b — Manual UAT checklist

Headless CI cannot verify on-screen pixels, GUI button clicks, or a live
MotherDuck round-trip. These join the standing UAT backlog
(P4b/P4c/P5b/P5c/P6a/P8/P9a). Run on a real desktop build with a MotherDuck
account.

## Catalog "Cloud" group
- [ ] Connect MotherDuck (Connections panel → Connect, enter token). After
      connect, the Catalog shows a **Cloud** group listing the account's
      MotherDuck databases' tables, distinct from local **Sources**.
- [ ] A local CSV/Parquet source and (if attached) a SQLite file stay under
      **Sources**, NOT under Cloud.
- [ ] Catalog search (token-AND) filters the Cloud group like the others.
- [ ] Disconnect → the Cloud group empties (md databases cleared).

## Test connection
- [ ] With a valid stored token, click **Test connection** (Connected state):
      a transient "Connection OK" message appears; the status pill stays
      Connected.
- [ ] From Disconnected with a stored token, **Test connection** connects and
      shows "Connection OK".
- [ ] From Disconnected with NO stored token, **Test connection** opens the
      token-entry prompt (same as Connect).
- [ ] With a bad/expired token, **Test connection** shows the localized error
      ("MotherDuck token was rejected…") and the pill goes to Error.
- [ ] Any other connection action (Connect/Disconnect/Forget) clears the prior
      Test-connection message.

## Token hygiene (master-spec exit criteria)
- [ ] Token persists across a second window and an app relaunch (keychain).
- [ ] Token never appears in logs, `settings.toml`, or telemetry payloads
      (spot-check the log file + settings file after connecting). The
      `motherduck_token_never_appears_in_serialized_app_state` unit test guards
      the serialized-state surface automatically.

## Routing chip (regression)
- [ ] A query against a `md.*` table shows `· md`; a local-only query `· local`;
      a mixed query `· mixed`.
