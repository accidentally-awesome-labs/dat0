# dat0 P9a-2 — Manual UAT checklist (Save chart → persist + lineage)

Headless CI cannot click native panels, GUI menus, or the name-prompt overlay,
so the GPUI side of P9a-2 is build-, clippy-, and unit/integration-test-verified
but NOT exercised end-to-end. This checklist captures the manual passes a human
must run on macOS. It **joins the standing P4b / P4c / P5b / P5c / P6a / P8 /
P9a-1 UAT backlog** — none of that earlier manual UAT has been run yet either.

What IS covered by automated tests (no manual pass needed for these cores):

- `session::charts` upsert-by-name + `default_chart_name` seeding (lib unit).
- v8 → v9 session migration with empty `charts` (`tests/session_migration.rs` +
  lib unit); v9 persisted-version assertions in the e2e restore tests.
- `.dat0` writer → reader chart round-trip, field-for-field, plus tolerant read
  of a pre-P9a-2 package without `charts.json` (`tests/reader.rs`).
- `dat0 diff` charts dimension (Added / Removed / SpecChanged + `is_empty` +
  `render_text` + JSON shape) (`tests/diff.rs`).
- `dat0 inspect` lists charts in both text and `--json` (`tests/cli_replay_inspect.rs`).
- Lineage: a chart attaches as a descendant of its source table; an absent
  source is skipped without panic (`inspector::lineage` unit tests).

This doc covers only what a test harness cannot reach: the GPUI button / prompt /
toast / click-to-reopen, and the live persist-then-reopen-workspace round trip.

## Pre-req

- A built `dat0.app` (release or debug) on macOS.
- A scratch or saved workspace with at least one base table (drop a CSV).

## 1. Save a chart (chart panel → Save)

1. Open a table, click **Visualize** to open the chart panel; pick a chart type
   and at least one axis so a chart actually renders.
2. Confirm the toolbar **Save** button is **disabled** before any axis is set
   (empty chart → nothing to save), and becomes **enabled** once the source is
   bound and an axis (x or y) is set.
3. Click **Save**. Expect a name-prompt overlay **pre-filled** with the generated
   default:
   - both axes set → `"<Type>: <y> by <x>"` (e.g. `Bar: amount by region`);
   - else → `"<Type> of <bare source>"` (e.g. `Histogram of orders`).
4. Edit the name if desired, confirm. Expect an info toast/banner **"Chart saved"**.
5. Save a SECOND chart under a DIFFERENT name → two saved charts. Re-Save under an
   EXISTING name (case-insensitive) → it **overwrites** in place (no duplicate).

## 2. Persist across workspace save / reopen

1. With one or more saved charts, save the workspace and fully reopen it (or, for
   a located workspace, close and reopen the app on it).
2. Expect: the saved charts survive — verify via the Inspector lineage (§3) and
   by reopening one (§3.3). The session is persisted on the same trigger as any
   other session mutation; `session.json` is schema v9.

## 3. Inspector lineage — Chart node + click-to-reopen

1. Open the Inspector on the chart's **source table** (click the table, or open
   it and let the Inspector re-root).
2. Expect a **descendant** node for each saved chart whose source is that table:
   - glyph **📊**, label = the chart's name, edge label **"chart"**.
   - Multiple charts on one source appear as sibling descendants.
3. **Click the chart node** → the chart panel reopens **bound to the saved spec**
   — i.e. the saved chart type AND axis picks (x/y/group/color/title) are
   restored, NOT a blank chart. (This is the crux: reopen must NOT reset axes.)
4. A chart whose source table is absent (e.g. the table was dropped) must simply
   not appear in lineage — no crash.

## 4. Package round-trip (in-app export → CLI inspect / diff)

1. File → **Export as .dat0 Package…** from a session that has ≥1 saved chart.
2. `dat0 inspect proj.dat0` → expect a **Charts:** section listing each chart as
   `name (type, source)`; `dat0 inspect proj.dat0 --json` → expect a `charts`
   array with `name` / `chart_type` (lowercased) / `source`.
3. Export a SECOND package after adding/removing/retyping a chart, then
   `dat0 diff a.dat0 b.dat0` → expect a **Charts:** section with `+` (added),
   `-` (removed), `~ <name> spec changed` lines as appropriate.
4. Open the package read-only in-app (File → Open .dat0 Package…) → the saved
   charts hydrate into that window's session (reopenable via lineage as in §3).

## Notes

- No new chart **rendering** path is added in P9a-2 (it persists specs), so the
  P9a-1 Linux `font-kit`/plotters gotcha is not re-triggered. Render itself is
  reused from P9a-1 (the `run_plot_query` path) for click-to-reopen.
- Charts enter a `.dat0` only via **in-app export** (the CLI reads charts but
  cannot author them), so D-025's cold-CLI derived-origin flattening does not
  apply to the charts dimension.
