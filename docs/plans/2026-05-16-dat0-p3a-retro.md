## Outcome summary

P3a lands the engine-to-pixel hot path for Scratch mode: a dropped file
registers into the per-window DuckDB engine, surfaces in a virtualized
DataGrid (cell-render dispatch over `duckdb::arrow::RecordBatch`), and the
window survives crash recovery via `session.json`. Multi-window via Cmd-N
works; UDS forwarding from a second `dat0` launch arrives at the handler
(visual window-spawn from the UDS path deferred — PD-010). Both deferrals
gated on P3a — D-011 (`__debug_query_scalar` removal) and D-012 (catalog
`TableInfo` synthesis) — are closed.

Out-of-scope (per the locked P3a/P3b split): import wizard, command palette,
crash-recovery banner Open/Discard action wiring, empty-state hero, editable
Settings widgets (D-001), theme live-switch (D-002), Banner structured-shape
refactor. All carry over to P3b.

## Plan defects discovered (PD-NNN)

- **PD-008** — P3a plan T2 snippets use `fs4::FileExt` (no longer at crate root) and `interprocess::local_socket::traits::Stream::connect` (refactored in v2.x to a concrete `Stream` enum + prelude). Severity: trivial. **Closed in T2** (`a1a19f3`): adapted imports to `fs4::fs_std::FileExt` + `interprocess::local_socket::Stream::connect` with prelude.
- **PD-009** — P3a plan T6/T8/T18 snippets use `engine.catalog().get_tables()` — no such method. Severity: trivial. **Closed at use sites** (`324d89f`, `4b522b5`, `b8f04b7`): the real surface is `engine.get_tables()` via the `QueryEngine` trait. `execute_paged` likewise takes `(sql, offset, limit)` not `(sql, PagedOpts)` — adapted.
- **PD-010** — UDS-triggered visual window-open on second-launch deferred. `AsyncApp::update` borrows a `RefCell`-backed app state owned by the Cocoa main thread; calling from a tokio worker panics. Severity: low — spec §3.1's forwarding contract (second launch exits 0) is satisfied; only the receive-side visual spawn is missing. **Open** (target T17 follow-up or P3b). Suggested fix path documented in `docs/deferrals.md`: capture a `Sender<Box<dyn FnOnce(&mut App) + Send>>` before `Application::run` begins so a tokio task can post work into a GPUI foreground-executor loop registered during init.

**Non-PD lesson:** T8 shipped with a silent bug (double LIMIT/OFFSET — inline SQL clauses + engine wrapper) that the existing two tests (`page_for(500)` twice — both page 0) didn't catch. Caught by code-quality review and fixed in `01af70b` with three new tests exercising pages 1+, beyond-EOF, and real data verification. Lesson: when the test dataset choice silently masks the bug, the reviewer's "what's the smallest input that would distinguish behavior?" question is the critical one. The same `execute_paged` API surface that produced PD-009 also rewards careful test design.

## Lessons learned

1. **Pre-flight blocker check matters.** Local Metal Toolchain was missing on this dev box and Xcode itself had a `DVTPlugInLoading` failure that blocked `xcodebuild -downloadComponent MetalToolchain`. Cost: ~2h discovered after T0 and resolved interactively. Future P-phase entry checklist should run `xcrun metal --version` before T0 — fail fast instead of fail mid-T1.
2. **Combined-verify scales linearly with task count; full review scales with API-contact risk.** T1, T3, T9, T13, T14, T15, T16–T19, T20 all used combined-verify successfully. Full two-stage review was reserved for T0 spike, T2 (AppLock — OS-integration), T4 (Session — engine API contact), T6/T7 (D-012 closure), T8 (GridDataSource — API drift caught), T10 (window mount), T11 (drop wiring), T12 (cross-thread). The split kept subagent dispatch count to ~3× task count (vs ~4× if every task got the full review).
3. **Plan-vs-real engine API drift is the single biggest tax.** PD-008 + PD-009 are both forms of "plan snippet references API that's no longer at the documented path". The implementer's first-pass approach should always be: read the real source file BEFORE pasting the plan snippet. Three subagent dispatches over P3a paid a 5-10 minute "read engine source" detour and saved much more in fix-cycle time downstream.
4. **Tests must distinguish the bug.** T8 shipped twice (`4b522b5`) before the LIMIT/OFFSET interaction surfaced because both tests sampled the same page-0 fast path. The fix commit (`01af70b`) added three tests specifically constructed to fail the buggy code. Going forward, when reviewing tests, ask: "is there a smaller / simpler input that this test would not distinguish from the correct behavior?"
5. **Spec is authoritative for filenames + paths.** T4's `session.duckdb` was caught at review only because the code-quality reviewer cross-checked against spec §3. The combined-verify shortcut doesn't catch this class of drift because the plan snippet itself drifted from spec. Future spec-vs-plan deltas should flag at plan authorship.

## Recommendations for P3b

1. **Close PD-010 first.** P3b needs the UDS→GPUI cross-thread bridge for: (a) recovery banner Open/Discard actions (which post a tokio task back into GPUI), (b) import wizard cancel (same direction), and (c) the spec §5.5 "running instance opens new window on UDS message" path. Recommend implementing this as the first P3b task, before any UX surface.
2. **Banner structured-shape refactor must precede the recovery banner UX work.** P3a's T15 emits `push_warning_message(format!("Recovered previous session: {}", path.display()))` — a string. P3b's Open/Discard actions need typed `{ title, body, link, action }` fields. Refactor the Banner shape before wiring action callbacks.
3. **TableDelegate mount.** P3a ships a placeholder div in `WorkspaceShell::render` (T10) where the gpui-component Table widget should mount. T0 spike notes have the verbatim trait signature and the `GridDataSource` skeleton compiles. P3b's first user-facing task should mount the Table widget against the existing `data_source` field.
4. **Action / keybinding system audit.** Cmd-N landed via `cx.on_action(NewWindow)`. P3b's command palette (Cmd-Shift-P) will require a registry of actions + keybindings + descriptive metadata. Time-budget this audit before wiring the palette UX.
5. **Bench upper-bound vs real grid.** P3a's bench measures `render_cell` dispatch only (≈15 µs/frame for 50×4 cells, ~67 kfps). Once the Table widget is wired (P3b or follow-up), re-run the bench against the real widget chain. Expect a 3-5× slowdown from text shaping + GPU upload; that's still well within the 60-fps budget but useful for regression detection.
6. **WindowRegistry handle escape.** T12 noted the registry currently doesn't escape `Application::run` — T17's multi-window count assertion uses `Session` isolation as a proxy. If P3b adds last-window-closes shutdown behavior, the registry needs to be passable to GPUI close-handlers; consider refactoring `run_app` to return the registry handle (or storing it as `cx.set_global`).
