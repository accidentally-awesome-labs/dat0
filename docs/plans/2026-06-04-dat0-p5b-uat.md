## Autocomplete (T0–T2) — the headless-deferred T0 gate items
- [ ] Typing an identifier prefix (e.g. `s`) in the SQL editor shows a completion popup.
- [ ] Enter/Tab inserts the highlighted suggestion into the buffer.
- [ ] `tablename.` suggests **that** table's columns (qualified completion); a wrong/unknown qualifier suggests nothing.
- [ ] Bare prefix suggests tables + columns + curated functions (e.g. `coa` → `coalesce`); empty word with no qualifier suggests nothing (no whole-schema dump).
- [ ] A table created via **Save as Table** appears in completions on the next keystroke (snapshot refresh after run/create).
- [ ] New tabs (the `+` and history/saved-query loads) also have working autocomplete.

> NOTE: T0's three visual bullets (menu render / insert / dot-path) were recorded `UNVERIFIED(headless)`
> — these are exactly the items to confirm here. The provider logic is unit-tested (T1, 9 tests);
> only the live menu render/insert was deferred per the plan's documented fallback.

## Query history (T3–T5)
- [ ] The 🕘 clock button in the console toolbar opens the history list (newest first), each row showing a first-line preview + `ok/err · N ms`.
- [ ] Clicking a history row loads that SQL (full buffer) into a **new** tab; the overlay closes.
- [ ] History survives app relaunch (persisted in `session.json` v6); capped at 100 entries (oldest dropped).
- [ ] A failed run records `err`; a cancelled run records `err`; a successful run records `ok`.

## Saved queries (T6–T8)
- [ ] The 💾 button opens the name modal; entering a name saves the active tab's SQL (upsert by case-insensitive name).
- [ ] The 📑 button opens the saved-query picker; clicking a name loads its SQL into a new tab.
- [ ] The ✕ on a picker row deletes that saved query; the list updates.
- [ ] Saved queries survive relaunch.
- [ ] Cancelling the name modal saves nothing.

## Save as Table — both paths (T10–T11)
- [ ] **Console path:** with a `SELECT` under the cursor, the ⤓ Table button → name modal → creates a queryable derived table (lineage recorded as `Sql(<raw statement>)`).
- [ ] A name collision or bad SQL surfaces inline in the results Error region (no modal — PD-021 respected).
- [ ] **Grid path:** with an active grid view + a non-empty transform stack, the PipelineBar "Save as Table" pill → name modal → creates a derived table (lineage recorded as `Transform{parent, ops}` — verified by `catalog_origin::create_table_records_both_origins`).
- [ ] The pill is hidden when there is no active view or the transform stack is empty.

## Timing chip (T9)
- [ ] After a run completes, the console shows `⏱ N ms · local` (idle-only; hidden while running).

## Command palette (T12)
- [ ] The 5 new actions (`sql.save_query`, `sql.load_query`, `sql.history`, `sql.save_as_table`, `view.save_as_table`) appear in the command palette (descriptors-only per D4; the real entry points are the buttons above).

## Known non-blocking follow-ups (from per-task + whole-feature review)
1. **Subscription rewrite not runtime-tested.** T8 switched the console event subscription `cx.subscribe` → `cx.subscribe_in` (NamePrompt needs a `&mut Window`) and added a `&mut Window` to `on_sql_console_event`. Proven sound by static analysis (no `SqlConsoleEvent` is emitted outside a window update) but not covered by a `TestAppContext` integration test. A smoke test over `SaveQuery`/`ShowSaved` would close the gap.
2. **Overlays not mutually exclusive.** The name-prompt, saved-picker, and console-internal history overlays can be `Some` simultaneously (stacked, cosmetic — not a correctness issue).
3. **Grid Save-as-Table error is log-only.** `save_view_as_table` failures `tracing::warn!` with no UI surface (the grid has no Error region equivalent). Consider a toast/banner in P5c.
4. **Lineage fidelity is per-path.** `Transform.parent` stores the (quoted) base-table identifier; the console path stores the raw statement in `Sql`. Fine for P5b.
5. **Double `session.json` write per run.** `set_query_history` + `persist_sql_console` each do a full atomic write. Correct (no data loss — second write includes the first's in-memory changes) but a future single-write consolidation is possible.
6. **Engine `create_table` now honors its `origin` param** (was discarding it since the T2 bootstrap stub). User-approved scope addition; verified safe (no app consumer read origins; `catalog_origin` tests green; regression-proven by re-injecting the old bug). This also retroactively corrected T10's lineage.
