## Plan defects discovered (PD-NNN)

- **PD-005** — P2 plan T3 snippet uses `&*conn` triggering clippy `explicit_auto_deref` under `-D warnings`. Severity: trivial. **Closed in T3** (commit `4418cbd`) by replacing `&*conn` with `&conn` in `apply_migrations_real`.
- **PD-006** — P2 plan T12 fixtures snippet uses bare `rng.gen::<…>()` calls; `gen` is a reserved keyword in Rust 2024 (workspace edition). Severity: low. **Closed in T12** (commit `0cc61bd`) via raw-identifier escape `rng.r#gen::<T>()`. Rand 0.8 retained (a future task can drop the escape if it adopts rand 0.9 workspace-wide).
- **PD-007** — P2 plan T14 snippet calls non-existent `error_ux::banner::push_banner` with mismatched `Banner` shape (`{ title_key, body_key, link }` vs P1's actual single-message `Banner`). Severity: low — the plan itself flagged the risk. **Closed in T14** (commit `9ea964b`): added a minimal `banner::push` / `banner::drain_pending` queue and concatenated title + body via `i18n::t` into `Banner::warning()`.

**Lesson, non-PD:** T7 hit a related "plan-snippet-vs-toolchain" issue — the plan's `info_span!().entered()` block was `!Send` across `.await` boundaries inside an `#[async_trait]` impl. Caught by code-quality review and remediated via `#[instrument]` attribute (fix commit `5eccb47`). Not a PD because it didn't manifest until the `.await` wiring was real, but it shares a root cause with PD-005/PD-006: plan code that compiles in isolation but fails under the actual workspace toolchain + edition.

## Lessons learned

1. **T0 spike is essential.** T0's finding that `duckdb::Statement::stream_arrow().Iterator::Item = RecordBatch` (bare, not `Result<RecordBatch>`) cascaded through the T7 / T8 streaming design. Without it, downstream tasks would have written `?` over the iterator and shipped silent error collapse without realizing. The cost of doing T0 first (~4h) saved an unknown but-substantial debugging tail later.
2. **Plan-snippet-vs-toolchain tension is real.** PD-005 (`&*conn`), PD-006 (`gen` keyword), and the T7 `EnteredSpan` `!Send` issue all manifested as plan code that compiled at authorship but failed under `-D warnings` or Rust 2024 edition or `async_trait` boundaries. Future plans should run their snippets through `cargo clippy -D warnings` on the target toolchain before lockdown.
3. **P1 primitive APIs drift between plan and reality.** T14's Banner integration adapted to P1's actual single-message API rather than the structured shape the plan assumed. The plan correctly flagged this risk inline; PD-007 captures the adaptation. Going into P3, treat P1 primitives as authoritative — read the file before quoting it.
4. **Combined-verify is the right shortcut for verbatim plan code.** T1, T5, T6, T9, T13, T18 used combined-verify successfully — plan-verbatim mechanical work doesn't need two-stage review. Reserve full review for genuine API-contact tasks (T2, T7, T8, T11b, T16) where the plan-vs-reality drift surfaces.
5. **Test-time extension install caches well across runs but is brittle cold.** T11b's `OnceLock` + per-process scratch tempfile pattern works in practice; T13's CI priming step (a tiny `cargo test -- attach_dispatch` to warm `~/.duckdb/extensions/`) sidesteps the documented multi-process race without code complexity.

## Recommendations for P3 (Scratch mode + DataGrid)

1. **Workspace-DB concurrent-open serialization.** P2 deferred this. P3 SQL Console + scratch mode will be the first surface where workspace state matters; budget time for either a file-lock approach or a single-process workspace orchestrator before SQL Console lands.
2. **Grid widget must consume `duckdb::arrow::record_batch::RecordBatch` directly.** Any PR that adds a standalone `arrow = "..."` workspace dep should be rejected at review — would silently break the type-chain that exit-criterion #11 protects. A grep gate (`! grep -r '^arrow = ' Cargo.toml crates/*/Cargo.toml`) is cheap to add to CI.
3. **`__debug_query_scalar` must be removed once T7's `execute()` is wired to test code paths.** It's `#[deprecated]` from T2 fix-up. P3's first batch of tests should consume the public API directly; the helper can be deleted in a P3 cleanup commit.
4. **Plan code samples should compile at author time.** Future plans benefit from a `plan-snippets` test crate that holds executable copies of plan-quoted code, ensuring `cargo check` over the plan repo catches PD-005 / PD-006-class issues before execution.
5. **Banner primitive needs a structured shape.** P2's adaptation got us through T14, but `Banner` should grow `{ title, body, link, action }` fields when P3 surfaces banners with calls to action. Avoid the inline-concat-into-message pattern beyond P2.
