---

## 1. Framing

The master-spec assigns the **design** of first-run onboarding to P9c and its
**implementation** to P11. P9c-3 is therefore a pure design slice: it produces
wireframes + content, no code. It is the natural last P9c slice because onboarding
design benefits from the app being feature-stable (charts, MotherDuck, AI all
present) — but since it ships no code, it has no runtime dependency on P9c-1/P9c-2.

---

## 2. Scope (from master-spec exit criteria)

Committed to `docs/design/onboarding-v1.md`:

- **First-run splash** — wireframe + copy for the initial welcome screen.
- **Sample workspace** — which sample dataset(s) ship, and the "Try with sample
  data" entry point (note: the `Scratch`-mode empty-state hero + "Try with sample
  data" buttons already exist from P3 — design should build on, not duplicate).
- **Skip-able tour** — the tour **script**: ordered steps, what each highlights,
  copy, and the skip affordance.
- **README polish** notes (first-run section).

---

## 3. Key decisions to resolve at brainstorm

- **Sample dataset** — which bundled dataset best showcases dat0 (CSV import →
  grid → filter/sort → chart → SQL → profile); size; licensing.
- **Tour scope** — how many steps, which features (import, grid edit, pipeline,
  charts, SQL console, catalog/inspector, AI); one linear tour vs feature-tagged
  tooltips.
- **Splash content** — value proposition copy; primary CTA (open file / try
  sample / open recent).
- **Visual companion** — this slice is genuinely visual (mockups, wireframes);
  **offer the Visual Companion** at the brainstorm.

## 4. Out of scope

- All implementation (first-run detection, splash window, tour engine, sample-
  workspace bundling) → **P11**.
- No code, no tests, no session/settings change in P9c-3.
