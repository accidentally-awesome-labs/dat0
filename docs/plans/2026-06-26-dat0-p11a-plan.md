# P11a — First-Run & Onboarding Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make dat0's first-run experience real — wire the dead empty-state hero, add the first-run value-prop band + featured `demo.dat0` CTA + a skip-able 7-panel tour carousel, and persist a `first_run_done` flag — implementing the approved `docs/design/onboarding-v1.md`.

**Architecture:** The empty-state hero (`empty_state.rs`) is a non-functional skeleton today; its sample buttons and recents column have no handlers and there is no working sample-open path. This plan wires those buttons to the *already-working* mechanisms (`file_drop::handle_drop`, `Recents`, `cx.prompt_for_paths`, `unpack_package_into`), then layers the first-run enrichment on top, gated by a new `Settings::first_run_done` flag. Pure decision logic (which hero mode, whether to auto-tour) is unit-tested; GPUI render/modal code gets construction/smoke tests plus manual UAT, matching the dat0 house pattern. The carousel modal mechanism is a GPUI unknown, resolved by a T0 spike before the carousel task.

**Tech Stack:** Rust, gpui (pinned rev), gpui-component (Dialog/Modal, pinned rev `0f0ab35`-era), DuckDB engine, `dat0-i18n` (`t()` → `strings/en.json`), `serde`/`toml` settings, `include_bytes!` bundled assets.

## Global Constraints

- **Design source of truth:** `docs/design/onboarding-v1.md` (D1–D5) and `docs/plans/2026-06-26-dat0-p11a-design.md` (P1–P6). Acceptance checks = design §8 / §10.
- **i18n:** every user-facing string goes through `dat0_i18n::t("…")` with a new key added to `crates/dat0-i18n/src/strings/en.json` (flat dotted-lowercase keys, e.g. `onboarding.tour.p1.title`). English-only values at v1. Missing keys render the key verbatim, so a typo'd key shows up immediately. The P10c referenced-key check (warn-only) must stay green.
- **Copy invariants (verbatim, must survive):** tour panel 4 states AI-drafted SQL **is reviewed before it runs**; panel 7 states AI is **off until a key is added** and data stays local. (`onboarding-v1.md` §5.)
- **Never-auto-run:** the demo workspace's pre-filled SQL tab must NOT auto-execute; the user clicks Run. (`onboarding-v1.md` §6.)
- **Settings:** mutate only through `SettingsStore` atomic helpers (`load_or_default` → mutate → `save`); never hand-edit `settings.toml`. Bump `Settings::schema_version` default 1→2. Absent `first_run_done` must deserialize to `false` (P3).
- **`demo.dat0` authoring:** the artifact MUST be produced via **in-app** `.dat0` export, never the cold CLI exporter (D-025: cold export flattens derived-origin lineage; in-app preserves it).
- **Commits:** one per task minimum, frequent within. Sign off every commit (`git commit -s`) — DCO is enforced. Co-author trailer: `Co-Authored-By: Claude Opus 4.8 (1M context) <noreply@anthropic.com>`.
- **Per-task gate (run before marking a task done):** `cargo fmt --all`, `cargo clippy --workspace --all-targets -- -D warnings`, and the task's tests green. Workspace test gate at the end (T13).
