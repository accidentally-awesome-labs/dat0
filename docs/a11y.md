# dat0 Accessibility (a11y) Audit — production v1

> **Status:** production-v1 release gate. Re-audited **2026-08-13**, against the
> Dioxus build. Supersedes the 2026-08-08 AX1 revision, which audited the GPUI
> build and was invalidated wholesale by the GPUI→Dioxus migration — not because
> its findings were wrong, but because it measured a UI toolkit that no longer
> exists.
>
> This file is the committed checklist and audit result required by
> `docs/specs/2026-04-26-dat0-design.md` §21.2 — the checklist items are at
> `:1202-1207` and the P10 exit line that names this file is at `:1216`
> ("A11y checklist passes (committed checklist + audit results in `docs/a11y.md`)").
>
> Sections: (1) the §21.2 checklist, (2) WCAG contrast, (3) keyboard
> reachability, (4) the screen-reader stance, (5) the tightest-pair watch.

## 0. What the migration changed

The previous revision was not sloppy; it was overtaken. dat0 rendered through
GPUI, a native toolkit with no accessibility bridge. It now renders DOM into a
WebView (wry/WebKit on macOS, WebKitGTK on Linux). Every row below follows from
that one fact.

| The old document said | Today |
|---|---|
| a11y annotations compile to no-ops in release, behind `a11y-capture` | ARIA **ships in release**. `pub mod a11y;` carries no `cfg` (`crates/dat0-ui/src/lib.rs:15`), and the crate declares only three features — `perf-harness`, `gallery`, `visual` (`crates/dat0-ui/Cargo.toml:17-27`) |
| `a11y-capture` gates an AccessKit `TreeUpdate` that `kittest` reads | Both are gone from the tree, and `crates/dat0-ui/tests/no_toolkit_deps.rs` fails the build if they return |
| Screen readers cannot see dat0 without forking GPUI | The substrate objection is gone — a WebView exposes ARIA natively. See §4 for what that does and does not entitle us to claim |
| `theme_contrast_gate` measures 24 hand-listed text pairs | `crates/dat0-core/tests/theme_tokens_contrast.rs` measures every semantic ink against every ground it is painted on, and fails when a new token is added without being measured or excused |
| `A11ySnapshot::capture` reads a render-time node collector | `crates/dat0-ui/tests/support/mod.rs` queries a VirtualDom mirror — `by_a11y_id`, `by_role`, `by_label`, `tab_order` |
| Tab did nothing in the cell editor (PD-020) | A plain `<input>` does not swallow Tab. `cell_editor_nav.rs:358` pins the walk |

The one thing that did **not** change is the vocabulary. `AccessRole`,
`data-a11y-id` and the tab-stop discipline carried over intact
(`crates/dat0-ui/src/a11y.rs`), which is why the suites below read as
continuations rather than rewrites.

## 2. WCAG contrast

### Method

`crates/dat0-core/src/theme/contrast.rs` implements WCAG 2.1 relative luminance
and contrast ratio over `#rrggbb` strings, plus `composite_over` so a translucent
token can be measured as it is actually painted. It is pure — no UI toolkit — so
the gate runs headless in CI.

`crates/dat0-core/tests/theme_tokens_contrast.rs` (11 tests) is the gate:

```bash
cargo test -p dat0-core --test theme_tokens_contrast
```

Thresholds: **≥ 4.5:1** for text (WCAG 1.4.3 AA), **≥ 7:1** in high-contrast
(1.4.6 AAA), **≥ 3:1** for non-text (1.4.11).

The gate is exhaustive by construction, which is the substantive improvement
over the list it replaced. `every_token_is_measured_excused_or_classified`
fails when a token is added to `ThemeTokens` and not measured, so the coverage
cannot silently rot; `ungated_entries_are_real_and_still_needed` fails when an
exemption outlives the thing it excused. There is no way to add an unreadable
colour and no way to quietly stop measuring one.

Two rules are enforced beyond ratios, because they encode mistakes already made:
`only_amber_named_tokens_carry_the_amber_hex` (amber is a fill, never body text
— the reason a separate `--d0-amber-text` exists) and
`the_modal_scrim_actually_dims_what_is_behind_it`.

### Results

All pairs pass in all three builtins. Per-theme minima:

| Theme | Tightest text pair | Ratio | Floor |
|---|---|---|---|
| light | `--d0-chrome-muted` on `--d0-tab-hover` | 4.74:1 | 4.5 |
| dark | `--d0-chrome-muted` on `--d0-chrome-raised` | 4.75:1 | 4.5 |
| high-contrast | `--d0-ink-on-amber` on `--d0-amber` | 9.18:1 | 7.0 |

Two neighbouring gates keep those numbers meaningful.
`crates/dat0-ui/tests/style_lint.rs` fails on any colour literal outside `:root`,
so every painted colour is a token the gate above measures — a hardcoded `#888`
would otherwise be invisible to it. `crates/dat0-ui/tests/theme_live_switch.rs`
asserts a theme switch rewrites every token from one document, making a
half-swapped palette (the historical defect: a light ground under a dark brand
measuring 1.97:1) unrepresentable rather than merely detected.

## 3. Keyboard reachability

### What the harness can and cannot assert

`crates/dat0-ui/tests/support/mod.rs` mounts real components against a
VirtualDom mirror. It queries by `data-a11y-id`, `aria-label` and `role`; it
dispatches real events; `tab_order()` returns nodes with `tabindex="0"` in
document order, so roving `-1` children are correctly excluded.

**It is not a browser.** There is no layout, so nothing in these suites can
answer "is this visible" or "what are its bounds" — `mouse()` zeroes every
coordinate specifically so no test can assert on fictional geometry. Focus is
harness state, because there is no `document.activeElement`.

Three modal-trap guarantees therefore cannot be settled here at all — Tab
wrapping at the last stop, Tab pulling focus back when it has escaped, and
dismissal handing the keyboard back to the opener. Those are the browser's own
focus model and live in `crates/dat0-ui/examples/modal_trap_probe.rs`, which
runs the real `CAPTURE_JS` / `CYCLE_JS` / `RELEASE_JS` in a real document. The
headless suites assert the observable half and say so.

### The suites

158 tests, 15 binaries, no feature flag. `cargo test -p dat0-ui`.

| Suite | Tests | Pins |
|---|---:|---|
| `keyboard_nav` | 8 | Hero controls are all in the tab order and all keyboard-activatable; nothing is reachable by mouse alone; Tab reaches the grid, then arrows move the cell |
| `sql_console_nav` | 18 | The console is drivable end to end; the tab strip is one stop however many tabs are open |
| `sql_console_transient_nav` | 23 | Which transient bar owns the keyboard, and the innermost-surface rule for Escape |
| `ai_nav` | 14 | Every control is a real button with the name it is announced by; Forget goes inert rather than unmounting under the user |
| `cell_editor_nav` | 13 | Tab walks the row and stops at its ends; a refused value keeps the editor open |
| `modal_nav` | 11 | Tab-ring composition: a radio group is one stop, not one per radio |
| `catalog_nav` | 11 | Tree is one stop with roving rows; a click moves the keyboard cursor too, so the two never drift |
| `tab_strip_nav` | 11 | The strip is one stop; each tab announces whether it is selected |
| `modal_trap_nav` | 10 | The trap as a keyboard user meets it — one Escape must not walk two rungs of the ladder |
| `a11y_content` | 8 | Rendered values announced through the a11y layer: gridcells carry column and value |
| `sidebar_nav` | 8 | Section structure, format swatches, and session round-trips |
| `input_nav` | 7 | The field/shell boundary: Enter confirms once; Escape is left for the dialog |
| `command_palette_nav` | 7 | The chord is inert while a modal is open; Tab never leaves the open palette |
| `recents_nav` | 5 | Tab reaches the recents list past titlebar, strip and sidebar |
| `a11y_spike` | 4 | The contract itself: a rendered name locates a control and round-trips to its stable id |

### The escape ladder

Precedence is data, not nested conditionals:
**Modal → Palette → SqlConsole → Global**, first match wins
(`crates/dat0-ui/src/keys.rs:13`). `Cascade` is rebuilt from shell state on every
keystroke so it cannot go stale, and there is exactly one `onkeydown`, on the
shell root (`crates/dat0-ui/src/components/shell.rs:335-352`).

There is deliberately **no global Escape row** — `escape_is_inert_with_nothing_open`
asserts the absence, so a future "helpful" global binding cannot silently take
Escape away from the surface that owns it.

## 4. Screen-reader stance

**The substrate objection is gone.** The previous revision's rationale was that
GPUI exposes no accessibility tree and AccessKit was absent from the pins, so a
screen-reader-navigable tree was not exposable without forking the toolkit. dat0
now renders DOM into a WebView, and a WebView exposes ARIA to VoiceOver and Orca
natively. Nothing needs to be bridged.

What ships, in release, unconditionally:

- `role`, `aria-label`, `aria-selected`, `aria-hidden` and `tabindex` on every
  annotated node — `crates/dat0-ui/src/a11y.rs`, no `cfg`.
- A modal trap that sets `inert` and `aria-hidden` on every sibling of the scrim
  (`crates/dat0-ui/src/components/modals.rs:320-331`). This closes something GPUI
  could not: `occlude` blocked the mouse only, and a screen reader still walked
  the shell behind an open dialog.
- `role="alert"` reserved for genuine interruptions —
  `only_a_failure_interrupts_the_reader` (`a11y_content.rs:382`) fails if a
  routine banner claims it.

**What is not claimed.** No screen-reader UAT has been performed. Shipping
correct ARIA is necessary, not sufficient: reading order, announcement verbosity
and grid semantics under a real screen reader are unverified, and this document
will not assert a pass it has not observed. The honest position for v1 is that
the mechanism is present and the vocabulary is dense, and that the first
VoiceOver pass is owed work rather than a formality.

D-015 was closed by the migration — the AccessKit bridge it tracked is moot. The
follow-up it named (grid selection semantics, the Connections attachment list,
the token-prompt modal) survives that closure and is the natural scope of a
first screen-reader pass.

**The v1 a11y baseline remains: operability + AA contrast.** Every interactive
element reachable and operable by keyboard (A1), focus rings measurably visible
(A2), every colour pair meeting WCAG 2.1 AA (A3/A4) and AAA in high-contrast.

## 5. Tightest-pair watch

The pairs with the least headroom. The gate catches a regression automatically;
this table exists so a reviewer knows which edits are dangerous *before* making
them. Measured 2026-08-13 with `contrast_ratio` over the committed builtins.

| Rank | Pair | Theme | Ratio | Floor | Headroom |
|---|---|---|---|---:|---:|
| 1 | `--d0-chrome-muted` on `--d0-tab-hover` | light | **4.74:1** | 4.5 | 0.24 |
| 2 | `--d0-chrome-muted` on `--d0-chrome-raised` | dark | 4.75:1 | 4.5 | 0.25 |
| 3 | `--d0-chrome-muted` on `--d0-tab-hover` | dark | 4.80:1 | 4.5 | 0.30 |
| 4 | `--d0-chrome-muted` on `--d0-chrome` | dark | 5.00:1 | 4.5 | 0.50 |
| 5 | `--d0-chrome-muted` on `--d0-chrome` | light | 5.06:1 | 4.5 | 0.56 |
| 6 | `--d0-error` on `--d0-surface` | dark | 5.22:1 | 4.5 | 0.72 |
| 7 | `--d0-chrome-muted` on `--d0-chrome-raised` | light | 5.39:1 | 4.5 | 0.89 |
| 8 | `--d0-error` on `--d0-canvas` | dark | 5.55:1 | 4.5 | 1.05 |

**`--d0-chrome-muted` is the token to watch.** It holds seven of the eight
tightest pairs, in both themes, because it is deliberately quiet text on chrome
that is deliberately close to it. Any adjustment to it, or to a chrome ground it
sits on, must re-run the gate before it is committed — and must darken the ink
rather than relax the threshold.

Never relax a threshold. Never add an exemption to dodge a failing pair. The
precedent (UI-redesign A3) is that the gate drives the final palette values, not
the other way round.
